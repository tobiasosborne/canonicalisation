# tools/

**Purpose.** Small standard-library-only developer tools. No dependencies, no network.

**`hexdump_stream.py`.** Strict parser and pretty-printer for `CDAG-2` streams (spec §4.1): header (`43 4e 02`, schema, action, `n`), `q`, records, root; prints each record with its byte offset and rejects trailing bytes. Usage: `python3 tools/hexdump_stream.py 434e0200...` (spaces allowed), `-f FILE` (hex text, `-` for stdin) or `--raw FILE`.

Coverage: tags `01`-`05` and `09` are parsed and checked strictly (atoms in domain, child references below the parent index, sets/multisets increasing, positive multiplicities, shortest `Nat`, sorted arcs, reachability, root is last). Tags `06`, `07`, `08` and `0a` are also parsed: `Perm` per §4.1 (increasing sources, no fixed pairs, bijection on the support), `Group` per §9.4 (both modes, structure only: blocks increasing, ordered by least point and disjoint; no group-theoretic validation of the generated group), and named relation records per §4.1. It does not re-derive the canonical DAG numbering of §4.2 and is not a certificate checker.

**Tests.** `tests/python/test_hexdump_stream.py` (the six §7.4 streams plus malformed variants).

**`canon-cli.c`** (slice S1, built as `build/make/canon-cli` by `make`, `canon-cli` by CMake). Links `libcanon` through the public header only. `canon-cli p1-subset --n N --gens "a0,a1,...;b0,..." --atoms "x,y,..." [--max-nodes K] [--id CASE]` solves `CANONICAL_IMAGE` under P1 and prints one `refs/compare/FORMAT.md` record (`CASE`, `0001`, status, trace hex, bytes hex, witness or `-`). `--gens ""` is the trivial group and `--atoms ""` the empty subset; `--max-nodes` sets the §11.1 NODE quota (0 = default). Exit 0 on `COMPLETE`, 3 on another status (hex fields empty), 2 on a usage error. Slice S2 adds `canon-cli p1-graph --n N --gens "..." [--colours "hex;hex;..."] [--arcs "s,t,labelhex,m;..."] [--max-nodes K] [--id CASE]` with the same record format and exit codes: an empty `--colours` makes every colour empty and is passed to the library as NULL arrays, so nothing is allocated per vertex and a huge `--n` reports `CAPACITY_LIMIT` like `p1-subset` (otherwise exactly N hex strings), a missing `--arcs` means no arcs, and a label may be empty hex; the multiplicity is passed through, so 0 gives `INVALID_INPUT`. Slice S3 adds `--backend chain|explicit` to both subcommands (default `chain`, the verified stabiliser chain; `explicit` is the S1 element table, kept as the test oracle, which refuses groups above its order limit with `CAPACITY_LIMIT`). Slice S4 adds the subcommands `min [--order cdag|simple-upper]` (`LEX_MIN_IMAGE`), `transporter` (`TRANSPORTER_ONE`), `stabiliser` (`STABILISER`) and `transporter-coset` (`TRANSPORTER_COSET`), all under profile `NO_TREE`. Their object is a subset (`--atoms`) or a graph (`--colours`, `--arcs`), chosen by `--kind subset|graph` or, without it, graph exactly when a graph option is given; the transporters take a target with `--target-atoms` or `--target-colours`/`--target-arcs` (default: the empty subset or the arc-free uncoloured graph). Every subcommand accepts `--witness any|deterministic` (spec §3 deterministic witness). Records now have seven fields (`refs/compare/FORMAT.md`): the last, `group_hex`, holds `Group(A)` (stabiliser), `Group(A) || Perm(r₀)` (nonempty coset), the `SIMPLE-UPPER-1` key (minimum under that order), or `-`; `bytes_hex` holds the minimum image's stream for minima; the witness is `g` for a minimum or a transporter hit and `-` for an exhausted empty transporter. `p1-subset` and `p1-graph` write `-` in the new field. Slice S5 adds `canon-cli p1-stream --n N --gens "..." --stream HEX` (the object is a CDAG-2 stream of degree N imported by `canon_object_create`; it need not be canonical), the object option `--stream HEX` and the target option `--target-stream HEX` for the S4 subcommands (`--kind stream`, chosen by default when a stream option is given; stream options do not mix with subset or graph options), and `canon-cli validate --stream HEX [--id CASE]` (a subcommand of the shared option parser that takes only those two options), which runs `canon_stream_validate` and prints the two fields `CASE<TAB>STATUS` (not a FORMAT.md record; exit 0 on `COMPLETE`, 3 otherwise). Hex of odd length and hex with a non-hex character are usage errors with distinct messages; a stream object without `--stream`, or a stream target without `--target-stream`, is a usage error. Slice S6 adds `canon-cli labeling --rho "r0,r1,..." OBJECT` (`CANONICAL_LABELING_COSET`, profile P1; `--rho` lists exactly N images and is required; the record carries the P1 trace on the target coordinates, `c`'s stream, the labeling `λ = ρt` as the witness and `Group(A) || Perm(λ₀)` as `group_hex`) and `canon-cli signed --signs "+-..." OBJECT` (`SIGNED_CANONICAL_IMAGE`, profile P1, the group built by `canon_group_create_signed` with one `+` or `-` per generator; the witness field ends in `;sign=+1`, `;sign=-1` or, for a certified zero with `bytes_hex` `00` and `group_hex` `-`, `;sign=0`). Both take the S4 object options (`--kind`, `--atoms`, `--colours`/`--arcs`, `--stream`). A missing or wrongly sized `--rho` or `--signs` is a usage error (exit 2). Slice S7 step 1 adds `--work-policy ID` to every subcommand except `validate` (the §11.1 v2.1 work-policy ID of the capacity descriptor, an unsigned 16-bit decimal: `1` the unpruned reference traversal, `2` orbit pruning of the canonical image; `0` or absent: the library default `2`; another value reaches the library and prints `UNSUPPORTED_ACTION`, exit 3) and `--prune on|off` as sugar for `--work-policy 2|1`; giving both, or either twice, is a usage error. The record format is unchanged. Note: the default is now the pruned policy, so with `--witness any` the canonical image's witness may differ from earlier releases (trace and bytes do not). Tested by `tests/python/test_e2e.py` and `tests/python/test_compare.py`.

The C decoder (`src/encoding/cdag_decode.c`) mirrors `hexdump_stream.py`'s rules and is stricter in two places: the third header byte is read as the encoding version (`UNSUPPORTED_ACTION` rather than a bad magic), and a `Nat` longer than 8 bytes is `CAPACITY_LIMIT`. Both reject overlapping rule-1 Group blocks (the tool since the S5 review). Conversely the tool rejects unsorted or repeated arcs, which the library accepts on import (combined, spec §4.1) and rejects only in `canon_stream_validate`.

**Governing spec sections.** §4.1, §9.4; `canon-cli`: §§3, 3.2, 4.1, 4.2, 4.4, 7, 8, 9.4, 11.1, 17.
