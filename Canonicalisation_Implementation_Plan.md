# Canonicalisation implementation plan

**30 September 2026 · aligned with architecture specification v2.0**

This is a plan for future implementation, not work authorised in the document-revision task. The [specification](Canonicalisation_C_Architecture_Specification.md) defines the contracts; the [response](Canonicalisation_Review_Response.md) records decisions against the reviews. Reviewed baseline: v1.0 at `fb014c9`, SHA-256 `924699142d622de142e63f1145c91b436612aa88653e77311da8ecb2d2cfb431`. No production C, Lean development, builds or benchmarks have been completed here.

## Dependencies and release sequence

Dependencies below are gates, not merely recommended reading. Every milestone retains its sources, scripts, versions, proof assumptions, failed/censored cases and review evidence. A smaller release may expose only completed adapters/objectives; it must return an explicit unsupported status for the rest. Correctness and capacity gates precede performance optimisation.

| ID | Deliverable and dependencies | Exit evidence |
|---|---|---|
| **M0: executable semantics and independent references** | Start from spec §§3–8, 11, 17. Implement two blind reference evaluators from the frozen P1, CDAG-2, order and API rules; no shared search/encoding code or exchange of implementation choices before comparison. Keep an independent tiny enumeration oracle. This milestone may use a development language; it does not define the production dependency set. | Hand-derived vectors reproduced; trace/byte/status/sign agreement including generated cases beyond oracle range; deterministic-witness agreement when requested; planted convention/sign/encoding error detected. Retain both implementations. Review every divergence as a possible ambiguity before fixing code. **Semantics-frozen gate** remains pending until this is done. |
| **M1: Lean semantic proofs and pure reference** | Depends on M0's reviewed definitions. Prove the right-action/opposite-group bridge, typed labeling cosets, representation-equivalence interface, tree canonicality, P1 termination, disjoint coset enumeration, complete reference stabiliser/transporter and signed zero/nonzero contracts. Mathematical finite groups may be supplied abstractly here, explicitly separated from efficient executable group data. | Kernel-checked theorems and a terminating pure reference, explicit assumptions ledger; no unsupported “implementation verified” claim. In particular prove λ=ρt reconstruction, complete Aλ, and the character theorem over the declared coefficient field. SIGN-COVER is unnecessary for this reference route. |
| **M2: certified constructive group operations** | Depends on M0; formal group-interface refinement depends on M1. Implement bounded permutation representations, orbit/transversal operations, deterministic construction and independent chain verification, sifting, stabilisers, base changes, tuple minimum, provenance DAGs and production Group(H) normal forms. Fix closure/rebuild policies and their operation/space bounds. | Small-group oracle membership/order/transport agreement, certificate mutation rejection, terminal-triviality and both-inclusions proof, generator-presentation independence, symbolic/sparse/dense agreement, byte/output bounds. Build/verify/rebase/sift timings are distinct. Include long Schreier paths, redundant input generators, changing bases and small support. A verified chain for harvested generators must never assert full object-stabiliser completeness. |
| **M3: concrete adapters and encoding proofs** | Depends on M0; proofs depend on M1, algebraic leaves on M2. M3a covers graph/subset/tuple actions, P1 signatures, trace/target rules, exact equality and wrapper conventions. M3b covers extensional DAG normalisation/encoding and subgroup/labeling-coset atoms. Tensor and auxiliary reductions are individually scoped M3c extensions with signed/free/dummy coordinate proofs. | One adapter theorem bundle at a time: decode factorisation, action, injectivity, equivariance, termination, projection and every bound used. DAG sharing/duplication and graph insertion-order tests; acyclic import checks and output-size evidence. Tensor wrappers require independent full double-coset convention vectors, never just internal-kernel tests. No use of `SimpleGraph` to conceal directed/multigraph semantics. |
| **M4: trustworthy scalar C and checker** | Depends on M0 and executable M2; each exposed adapter depends on the corresponding M3 contracts. The independently proved checker depends on M1/M2/M3 rules. Implement all requested reference consumers, partial-result flags, capacity planning, output sink and ownership/failure semantics before pruning. Add pruning only with its objective-specific rule. | Oracle/reference agreement, public API/FFI idempotence/invariance, signed cross-feed, verified odd witnesses and complete nonzero evidence. Fault injection, malformed/corrupt certificates, sanitizers, fuzzing and required C warnings pass in a later implementation environment. Independently reject omitted search coverage. State whether checked execution trusts compiled Lean/runtime or uses kernel-checked terms. Scalar C memory safety is not established by this gate alone. |
| **M5: serial and small-batch performance** | Depends on M4 and viable M2/M3 representations. Implement caller-owned-thread workspaces, immutable shared registries/groups, admission-time allocation, bounded caches, replay/trail tradeoffs and coordinate-transported skeleton reuse. Instrument first, then tune equivalent kernels. | Cold/warm/amortised boundary ledger; live-memory peaks including verification/output/provenance; deterministic capacity outcomes under different schedules/cache policies; no allocation/chain rebuild on an admitted hot path where promised. Cache-resident batch compute/branch/stream/collection models, root-discrete fraction, honest Δ/ρ/δ to applicable U/A/H floors and E targets. Matched pinned competitors, all censored cases and actual group structure recorded. |
| **M6: concurrent coverage abstraction and runtime** | Depends on M4; performance policy depends on M5. First prove the coordinator state machine independently of C, then implement the mutex-based publication/claim/split/link protocol, bounded helper ownership and trusted checkpoint/resume. | Abstract preservation and completion proof, retained representatives, failure/cancellation/reclamation tests, forced interleavings and helper joins; same complete bytes and capacity policy as serial. Root coverage survives stealing/replay/restart. Checkpoint corruption detection is not independent coverage verification. Untrusted resumption remains disabled until a checker covers its full coverage graph. Record work inflation and task-transfer costs. |
| **M7: C/runtime verification** | Separate programme, depending on the relevant M1–M6 contracts and a deliberately chosen concrete C/memory model. Prove data refinement for arrays, bounds/overflow, rollback, lifetime/aliasing, allocator/error paths; separately connect C17 atomics/OS primitives and concrete checkpoint protocol to M6. | Reviewed simulation/refinement theorems for a declared subset, explicit compiler/OS/runtime assumptions and exclusions. A pure Lean algorithm with analogous arrays is insufficient. Safety, search completeness, scheduler liveness under fairness and crash behaviour are separate claims. |
| **M8: ISA kernels and optional GPU** | Depends on M4/M5; parallel kernels also on M6. Scalar-equivalent SIMD may ship with tested assurance; formally verified claims need corresponding M7/ISA refinement. GPU is a distinct optional plugin, not a CPU release prerequisite. | Tail/overflow/duplicate-scatter/dispatch checks, scalar equality across pinned profiles, measured regime wins and memory impact. GPU additionally demonstrates buffer/event ownership, residency/transfer accounting, cancellation/fallback and complete end-to-end comparison against CPU. Future GPU floors never serve as CPU acceptance floors. |
| **H0: retrieve and audit optional hex leads** | Independent research gate for a later task permitting retrieval. Retrieve `leanprover/hex-graph-iso` and `leanprover/hex-perm-group` locally at **explicit full commit hashes**, not moving branches. The hashes are presently unresolved; do not invent them or depend on the repositories before this gate passes. No network/download is permitted in this revision. | Under `review_sources/formalisation/`, retain source/archives, full commit IDs, SHA-256 of each archive and inspected files, source URLs/timestamps, licenses, toolchains and a manifest. Inspect actual theorems, assumptions, executable/checker relation and configuration scope. Confirm or reject the claimed simple-undirected pinned-nauty and `checkChain` leads against code, not README/API alone. This does not require a build during acquisition if resources disallow one; any later build-dependent claim needs its own evidence. |
| **H1: optional reuse decision** | Strictly depends on H0; integration also depends on applicable M1–M4 interfaces. Decide whether the inspected code can discharge a bounded part of M2 or support a separately versioned graph-only profile. | Written theorem/interface match, convention bridge, license/toolchain decision and local reproducibility. If rejected/unavailable, use the independent M1–M4 route. Neither lead is assumed to cover arbitrary-G P1, directed/multi/hypergraphs, tensor adapters, signed completion or C runtime safety. |

The practical order is M0 → reference/group/adapters → M4 → M5 → M6/M8; M1 proofs and M2/M3 construction can overlap once interfaces are frozen. M7 remains a separate assurance track; omitting it means explicitly tested/certificate-checked C, not formally verified C. H0/H1 are optional and have no hidden edge into the independent route. Introducing a new canonical profile requires its own M0-equivalent gate and versioned ID.

## Review gates and obligations ledger

| Gate | Required before acceptance |
|---|---|
| Semantics frozen | M0 blind agreement, assigned grammar/profile/order, typed witnesses, capacities, golden vectors and wrapper contract review. The document is a concrete candidate; writing it alone does not pass this gate. |
| Mathematical reference complete | M1 proofs for image/minimum/transporter/stabiliser/signed reference, totality hypotheses and M2 group refinement as appropriate to executable claims. |
| Representations viable | M2 canonical generator/symbolic format; M3 shared DAG; M4 exact live-state admission/output streaming, including one-task failure. No cubic production group stream or occurrence expansion. |
| Scalar trustworthy | M4 independent evidence, checked coverage where advertised, mutation/fault tests and an explicit trusted-code ledger. |
| Performance honest | M5 scope-matched comparisons, all setup/output costs, U/A/H versus E distinction, CPU/GPU and cold/warm separation, reproducible gaps. |
| Optimisation admissible | Proof/equivalence or checker rule plus measured regime benefit. R1–R3 apply to shortcuts/racers/helpers; probabilistic discovery never certifies completeness. |
| Parallel/accelerated release | M6 coverage and ownership; M8 scalar equality, transfers/residency and work inflation. M7 is required only for the separately advertised concrete-verification guarantee. |

Maintain named open obligations rather than silently assuming results:

- **SIGN-COVER:** arbitrary-G tree/pruning detection of every odd automorphism. The complete-stabiliser reference discharges signed correctness without it; do not optimise away that search until this lemma is proved for the chosen profile.
- **PROFILE-EQUIV:** every faster splitter, decomposition, shortcut, cache transport and backend must reproduce P1 or carry a new profile ID. Image-only pruning and full-group coverage need different rules.
- **ADAPTER-FAITHFUL:** each tensor/auxiliary/custom reduction needs action/equality/projection and exact key/wire proofs. Wrapper tests cannot replace these.
- **GROUP-CERT:** actual BSGS/character certificates and practical construction policies need M2 proofs and cost accounting; deterministic construction alone is no speed argument.
- **RUNTIME-REFINE:** coverage transitions, C storage/atomics/reclamation and checkpoint trust boundary require distinct M6/M7 evidence.
- **SOURCE-GATE:** optional claims from McKay–Piperno Theorem 5, Niehoff, SeQuant, dejavu or hex must be supported by local primary sources and convention/scope checks before normative use. H0 is the mandatory gate for hex; other acquisitions need analogous provenance in a future authorised research task.

## Effort judgments and reconciliation

All ranges are **planning judgments**, not literature facts, measured delivery rates or commitments. Assume an experienced Lean/mathlib developer with access to a permutation-group specialist, frozen interfaces and ordinary tooling. Person-weeks are expert effort, not elapsed calendar weeks. They exclude new research whose scope is not yet fixed, and overlap makes their sum misleading.

The [referee report](Canonicalisation_Referee_Report.md), finding 17, assigns 2–6 weeks to the *abstract tree theorem* (A), several further weeks to reference algorithms (B), several months to group/profile and adapter proofs (C–D), and plausibly person-years to the C/runtime surface (E). The [formalisation review](Canonicalisation_Formalisation_Literature_Review.md) includes substantially more executable definitions and proof plumbing in its 8–16 week first milestone. These estimates concern different deliverables and do not conflict.

| Scope in this plan | Reconciled judgment | What the range includes |
|---|---|---|
| Narrow abstract canonical-tree theorem within M1 | 2–6 expert weeks | The referee's A; assumes group/action/refiner interfaces. It is not the whole M1. |
| Full M1 semantic/pure reference package | 8–16 expert weeks | The formalisation review's first milestone: convention bridge, orbit/coset algorithms, termination and reference proofs. Signed and capacity additions require re-estimation at M0; the inherited range is a baseline, not an assertion they are free. |
| M2 constructive certified groups | 12–36 expert weeks | Group arrays/orbits/chains/verifier and normal forms; matches “several months.” Benchmark-driven fast construction beyond the agreed scope requires re-estimation. |
| M3a plus the mathematical serial pruning/checker portion of M4 | 12–32 expert weeks shared | The formalisation review's useful-serial milestone. Do not charge this range once to each milestone. It excludes a full C memory-safety proof. |
| M3b selected general adapters | 12–32 further expert weeks | Extensional DAG, bounded auxiliaries and algebraic atoms, depending on agreed scope. M3c tensor reduction and signed fast proofs are not silently included. |
| Abstract protocol proof within M6 | 8–24 expert weeks | Ownership, representative coverage, cancellation and restart once the protocol is fixed. Concrete C atomics refinement belongs to M7. |
| M7 substantial concrete C/concurrency/ISA assurance | 1–3+ expert person-years | The formalisation review's range is consistent with the referee's “person-years”; full advertised coverage may exceed it. |
| M0, production C engineering in M4, M5/M8 tuning, H0/H1 and extra adapters | Re-estimate at their entry gates | No review supplies a defensible complete delivery estimate for these. Do not treat an omitted estimate as zero effort or add overlapping proof ranges to fabricate a calendar date. |

The next authorised implementation decision should be a bounded M0 scope and retained blind evaluators, followed by group/reference milestones. Re-estimate after M0 and after measured M2/M4 prototypes. No performance promise should be made before those measurements.
