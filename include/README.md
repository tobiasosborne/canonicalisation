# include/

**Purpose.** Public C17 headers of the `canon` library: `include/canon/canon.h` (opaque-handle API) and `include/canon/canon_version.h`.

**What may live here.** Only installable public declarations: enums, constants, opaque typedefs, prototypes, each carrying a one-line comment that cites its spec section. No internal types, no inline algorithms, no third-party headers.

**Governing spec sections.** §3 and §3.2 (objective tags, status, result flags), §4.1/§4.3/§4.4/§7.1 (frozen identifiers), §17 (API and ownership).

**Status.** Slice S1 implements the version functions, the context and `canon_capacity` descriptor, retain/release for every handle, `canon_group_create` (explicit backend), `canon_object_create_subset`, `canon_problem_create` (with its capacity argument), `canon_workspace_create`, `canon_solve` for `CANONICAL_IMAGE` under P1, the result accessors and `canon_result_encode`. Slice S2 adds `canon_arc`, `canon_object_create_graph` (coloured directed multigraph, spec §4.1) and `canon_object_create_simple_graph` (simple undirected wrapper); `canon_problem_create` accepts a graph object and checks the exact graph stream length against `max_output_bytes`. `canon_solve_batch` (S8) and the checkpoint functions (M6) remain stubs returning `CANON_UNSUPPORTED_ACTION`. Slice S3 adds `canon_backend`, `canon_context_options` and `canon_context_create_with_options` (the backend is fixed when the immutable context is created; the default `CANON_BACKEND_CHAIN` builds a verified stabiliser chain; `CANON_BACKEND_EXPLICIT` keeps the S1 element table as a test oracle) and `canon_group_order` (exact `uint64` order; `canon_group_create` refuses groups of order above `2^64 − 1` with `CANON_CAPACITY_LIMIT`; the multi-limb order is deferred, see `docs/slices/S4-notes.md`); `max_group_order` now bounds the explicit backend only. Slice S4 adds `canon_witness_mode`, `canon_problem_options` and `canon_problem_create_with_options` (a target object, the enumeration objectives `LEX_MIN_IMAGE` under `CDAG-BYTE-1` and `SIMPLE-UPPER-1`, `TRANSPORTER_ONE`, `STABILISER` and `TRANSPORTER_COSET` under profile `NO_TREE`, and the deterministic witness), the accessors `canon_result_group_bytes`, `canon_result_order_key` and `canon_result_transporter`, and implements `canon_result_verify_witness`; `max_search_nodes` counts P1 NODE tokens plus coset-enumeration visits of a solve. Slice S5 implements `canon_object_create` (schema `EXT-DAG-1`, action `ATOM-TRANSPORT-1`: a CDAG-2 stream of the given degree, strictly decoded and normalised; sharing, record order, unreachable records, non-canonical Group presentations and unsorted or repeated arcs are accepted, malformed streams are `CANON_INVALID_INPUT`, the relations record, graph records below the root and other schema/action/version IDs `CANON_UNSUPPORTED_ACTION`; a set of atoms becomes a subset object and a graph record a graph object, as the builders make them), adds `canon_stream_validate` (canonical form by byte identity, spec §4.2) and the capacity fields `max_nodes`, `max_refs` and `max_literal_bytes` (defaults `1<<20`, `1<<22`, `1<<26`; checked on the normal form at import against the context and at problem creation against the descriptor). Slice S6 adds `canon_group_create_signed` (signs validated by the lifted group, spec §8.4; `n + 2` must fit `uint32`, §11.1) and `canon_group_character`, the `rho` field of `canon_problem_options`, the objectives `CANONICAL_LABELING_COSET` and `SIGNED_CANONICAL_IMAGE` under profile P1, and the accessors `canon_result_sign` and `canon_result_labeling`; `canon_result_encode` writes the single byte `00` for a certified signed zero, and `canon_result_verify_witness` checks labelings and zero certificates. Slice S7 step 1 adds `canon_work_policy` with `CANON_WORK_POLICY_REFERENCE` (`0x0001`, the unpruned reference traversal) and `CANON_WORK_POLICY_ORBIT_PRUNE` (`0x0002`, orbit pruning of the canonical image, `docs/pruning-rules.md`), the last field `work_policy` of `canon_capacity` (spec §11.1 v2.1; default `0x0002`; unknown IDs `CANON_UNSUPPORTED_ACTION`) and `canon_result_work_policy` (the effective policy of a completed solve; a provisional reading of "recorded in results"); with `CANON_WITNESS_ANY` the canonical image's witness under `0x0002` is a valid witness that may differ from the unpruned one, while the deterministic witness is unchanged. All argument lists are provisional until M4.
