# Algorithm literature audit of the canonicalisation architecture

Reviewed against locally retained primary papers on 29 September 2026, for specification v1.0. Its baseline section/line references are historical; the [v2.0 response](Canonicalisation_Review_Response.md) records the adopted decisions and current sections. This note reviews mathematical scope and constructive algorithm support; it does not establish implementation correctness or measured performance. The TeX sources are the principal evidence, with locally extracted PDF text used to verify printed result numbers. All local links below resolve inside this workspace. Acquisition URLs, exact versions, SHA-256 hashes and extraction details are in [the main manifest](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/manifest.json) and [the supplemental manifest](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/manifest_supplemental.json). No TeX or source-supplied commands were executed.

The architecture correctly separates canonical images, prescribed minimum images and complete stabilisers. Its explicit right-action proof in §7.2 and normalized refiner in §7.3 are sound under their stated equivariance hypotheses. The strongest actionable literature finding is that §9.4 need not defer canonical generating sets as an unspecified future replacement: an existing constructive algorithm uses the planned group-kernel operations and reduces worst-case dense serialization from cubic point entries to O(n² log n). The corresponding group-conjugacy and general-object complexity claims require separate qualifications.

## 1. The leaf map and canonical-tree objective

R1 Remark 4.1 states that an exhaustive nonrepetitive list has a unique minimizing group element and that it is polynomial-time computable. Appendix Lemma 7.1 gives successive point-orbit minimization and point stabilizers, precisely the ingredients proposed in §7.2. See [Remark 4.1, TeX lines 800–805](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/2209.02534v4/paper.tex:800) and [Lemma 7.1 and its proof, lines 1226–1239](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/2209.02534v4/paper.tex:1226).

Using the specification's convention, if L is a complete atom list and h∈G, the two lists L and L^h have the same minimum G-image. Uniqueness gives t_(L^h)=h⁻¹t_L. Consequently (x^h)^t_(L^h)=x^t_L. Equivariant trees and invariant framed traces therefore give identical leaf-key sets. Taking their minimum is canonical. This is a directly checked argument using the specification's convention, rather than an unexamined transplantation of the paper's notation.

R1's corresponding canonical-tree construction first selects minimal path-stack information and then minimizes object images among the selected leaves: [Definition 4.3 and Lemma 4.4, lines 833–902](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/2209.02534v4/paper.tex:833). Its tree compatibility statement explicitly treats child order as immaterial: [Remark 3.3, lines 781–788](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/2209.02534v4/paper.tex:781). Thus §7 is supported in principle, but a concrete release profile still must specify the actual refiners, ordered partition construction, extraction of singleton lists, target-cell tuple and trace tokens. Abstract equivariance requirements are proof obligations, not implementations.

The review does not transfer the displayed MinPerm identity in R1 line 887 literally into the specification: its use of result and inverse permutations in lines 854 and 887–902 requires attention to notation. The self-contained uniqueness argument above supplies the needed identity in the specification's explicit convention. This note does not depend on diagnosing a defect in the paper.

## 2. Normalized group-orbit refinement

R1 Appendix Lemma 7.4 defines the refiner by sending the equivariantly extracted fixed list to its minimum image, applying a fixed-point refiner there and transporting back. It proves independence of the chosen transporter and refiner soundness: [lines 1273–1300](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/2209.02534v4/paper.tex:1273). Example 7.3 permits orbit labels and a fixed ordering of orbital graphs: [lines 1253–1271](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/2209.02534v4/paper.tex:1253).

For §7.3 specifically, if F^u=F^v=M, then u⁻¹v∈G_M. Every element of G_M preserves each of its orbits, including their prescribed order on the target domain. The ordered orbit partition transported back is consequently independent of u. If F changes to F^h, the result changes by h. This validates the baseline. The extraction and order of F must itself be equivariant; an implementation cannot use encounter order or arbitrary original atom IDs for that list.

## 3. General objects, composition and the size model

R2 models vertices and labeling cosets as atoms, and recursively builds typed sets and tuples. It explicitly treats cosets succinctly through generators and gives the precomposition action (Δρ)^μ=μ⁻¹Δρ. This supports §§2.1 and 3.1: [object definitions and actions, lines 39–90](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/1806.07466v2/articles/heredit.tex:39).

Its canonical-labeling requirements include the complete automorphism coset, not merely a chosen labeling: [CL1–CL2, lines 158–186](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/1806.07466v2/articles/heredit.tex:158). Lemma 9 proves object replacement by such cosets under the equal-canonical-image hypothesis: [lines 12–34](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/1806.07466v2/articles/objectReplacement.tex:12). The specification's insistence on complete cosets for composition is therefore justified.

Theorem 17 gives 2^{O(k)}N^{O(1)}, where N is input size and k the largest admissible-group orbit: [lines 19–27](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/1806.07466v2/articles/hereditarilyFiniteObjects.tex:19). This is an algorithm-specific bound. The specification correctly says its practical backtracker does not acquire it merely by accepting the same types.

R2 explicitly uses a DAG over the transitive closure, with encoding length polynomial in closure size, domain size and maximum tuple length: [lines 229–248](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/1806.07466v2/articles/heredit.tex:229). Its recursive computation memoizes by distinct subobject: [lines 74–83](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/1806.07466v2/articles/hereditarilyFiniteObjects.tex:74). Lemma 22 asserts polynomial injective encoding in this representation: [lines 42–48](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/1806.07466v2/articles/canGenSets.tex:42). An occurrence-unfolding serializer would abandon that size model and can produce exponentially many bytes. An extensional canonical DAG encoding and output-size accounting are required to make the planned nested-object adapter practical.

Corollary 19 concerns explicit codes with an exponential factor in word length and polynomial dependence on the number of words, with symbols fixed pointwise. It does not cover implicitly represented linear codes or automatically grant arbitrary symbol actions: [lines 122–137](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/1806.07466v2/articles/hereditarilyFiniteObjects.tex:122).

## 4. Canonical group bytes have an existing constructive improvement

R2 Lemma 21 states a polynomial-time presentation-independent generating-set algorithm for a labeling coset on an ordered domain: [lines 27–33](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/1806.07466v2/articles/canGenSets.tex:27). That statement alone does not quantify output size. Its cited original L2 Lemma 21 does: at most n log n coset elements, selected successively as the lexicographically least element outside the coset generated so far. It states presentation independence and gives a constructive proof: [statement, lines 140–147](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/1803.06858v1/articles/canonization.tex:140), [algorithm, lines 149–175](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/1803.06858v1/articles/canonization.tex:149). The locally retained PDF independently verifies printed Lemma 21 at lines 1134–1158.

The proof partitions by successive point images, tests which constrained coset is contained in the generated coset and recurses in the smallest branch that contains a new element. It explicitly invokes Schreier–Sims and polynomial-time standard group operations. This is implementable once the planned verified group kernel provides point constraints, membership and subgroup containment. It is not merely existential. The paper does not give a precise polynomial exponent, benchmark or C implementation.

With dense n-entry permutations, the cited output bound is O(n² log n) point entries. §9.4's full canonical transversal output is O(n³). A reasonable revision is to implement the constructive greedy canonical generating sequence in the early group-kernel phase and reserve the transversal scheme as a simple reference. The improved bound remains potentially huge at large n; it does not justify calling every group output compact or cheap. Equality tests should normally use exact group operations rather than materializing serialized normal forms repeatedly.

This ordered-domain normalization is distinct from finding the conjugacy class canonical image of a subgroup. R2 Corollary 20 gives 2^{O(|V|)}|Δ|^{O(1)} for permutation-group canonization by encoding every group element explicitly: [lines 143–153](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/1806.07466v2/articles/hereditarilyFiniteObjects.tex:143). The polynomial factor is in group order, not succinct generator length. It provides no bound polynomial in the size of a generator presentation for arbitrary subgroup-conjugacy canonization.

## 5. Perfect refiners establish expressiveness, not cheap computation

R3 Definition 4.2 makes a perfect refiner exact at the level of transporter sets: [lines 395–435](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/2112.05065v2/perfect-refiners.tex:395). This is different from saying a particular equitable-partition approximator immediately computes those transporter sets cheaply.

Base-domain graph stacks perfectly represent precisely the 2-closed groups, whereas extended graphs permit every subgroup: [Corollary 7.3 through Lemma 7.5, lines 836–859](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/2112.05065v2/perfect-refiners.tex:836). The paper immediately says the auxiliary witness may have size comparable to |G| and be impractical: [lines 862–863](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/2112.05065v2/perfect-refiners.tex:862). Its concluding discussion also separates search-size pruning from the cost of the refiner: [lines 1460–1468](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/2112.05065v2/perfect-refiners.tex:1460). These support §6.2's qualifications.

R3 defines an extended graph as an orbit under permutations of the auxiliary vertices: [§6, lines 646–668](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/2112.05065v2/perfect-refiners.tex:646). This formalizes why auxiliary numbering must not become semantic. It does not by itself prove that every chosen representative-based trace permits stopping when only base atoms are discrete; the adapter must establish that property.

For subgroup-conjugacy refiners, the set of orbital graphs is safe but loses information for general groups, with distinct 2-transitive groups explicitly illustrating noninjectivity. It is perfect on 2-closed groups: [§8.3.5, lines 1371–1397](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/2112.05065v2/perfect-refiners.tex:1371). Native subgroup membership and exact leaf checks remain necessary.

## 6. Complete transporter and stabiliser output

R4 Theorem 7.6 proves the baseline search returns every element in the constraint intersection: [lines 3681–3700](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/1911.04783v4/PermAlgoDigraphsJPWW_extended.tex:3681). Theorem 7.13 proves a specialized subgroup search returns a base and strong generating set: [lines 4136–4148](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/1911.04783v4/PermAlgoDigraphsJPWW_extended.tex:4136). These support the distinction between a witness, partial automorphism harvest and complete stabiliser in §8.3. They do not supply completion merely from sound generators discovered during another objective.

The coset decomposition in §8.1 is independently correct in the specification's right-action convention: the elements mapping a to b are exactly H_a t_b, so the children H_a t_b r are disjoint and cover H r. Minimum-image correctness still depends on preserving this coverage under each optimization. R1 Definition 4.3 selects a subset of leaves before minimizing images, so its canonical-tree objective cannot substitute for this proof.

## 7. Exponential IR lower-bound scope

L1 Theorem 3.2 gives a family of rigid graphs forcing 2^{Ω(n)} tree nodes for every constant k and every k-realizable selector, refiner and node invariant: [lines 311–319](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/1705.03283v1/ir-analysis.tex:311). The fixed-dimensional WL realizability requirements are defined at [lines 298–307](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/1705.03283v1/ir-analysis.tex:298). All automorphisms are supplied initially for free, and Proposition 3.1 divides tree size by automorphism-group order: [lines 278–285](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/1705.03283v1/ir-analysis.tex:278). Because the hard graphs are rigid, complete symmetry information cannot avoid the exponential lower bound.

This supports warnings about bounded-WL IR profiles and explains why smaller storage or SIMD does not remove their worst-case search growth. It is not a lower bound for arbitrary exact refiners, arbitrary adapters or all canonization algorithms. The authors explicitly leave growing WL dimension unresolved: [lines 1073–1076](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/1705.03283v1/ir-analysis.tex:1073).

## 8. Prescribed minimum images include NP-hard graph orders

Karp's retained scan has no text layer, so this verification uses selected local page images, not purported text lines or web summaries. In §4, printed p.93, completeness means NP membership and a polynomial reduction from SAT: [local page image](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/Karp_1972_page9.png). The Main Theorem on printed p.94 declares the listed problems complete; item 3 is CLIQUE with a set of k mutually adjacent vertices: [local page image](/home/tobiasosborne/Projects/canonicalisation/review_sources/algorithms/Karp_1972_page10.png). Complementing a graph transforms this problem into Independent Set.

The following further reduction is the reviewer's own argument, not a claim quoted from Karp. On a simple graph, let G=Sym(n) and encode upper-triangle adjacency in the order (0,1),(0,2),(1,2),(0,3),(1,3),(2,3),… with 0<1. The first binomial(k,2) bits describe the induced graph on labels 0,…,k−1. The lexicographically minimum image has an all-zero prefix of that length exactly when some k vertices form an independent set: an existing all-zero prefix beats every prefix containing a one. Therefore computing this prescribed minimum image in polynomial time would decide an NP-complete problem in polynomial time.

The conclusion applies to at least this supported encoding/order and is sufficient to rule out a universal polynomial guarantee for LEX_MIN_IMAGE unless P=NP. It does not claim every graph encoding order has the same reduction, an unconditional exponential time lower bound or NP-hardness of arbitrary canonical forms. The specification should identify the graph order precisely and keep this distinction visible.
