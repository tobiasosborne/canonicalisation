# src/symmetry

**Purpose.** Verified automorphism discovery and the known-automorphism subgroup used for pruning.

**Governing spec sections** (`docs/specification.md`, normative): §7.3 (pruning and A_known), §8 (objective-specific completeness), §9.2 (base change), §14.3 (R2).

**Status.** Implemented in slice S7 (`docs/slices/S7.md` §3.1–3.2; rules in `docs/pruning-rules.md`): `symmetry.h`/`symmetry.c`, the verified subgroup `A_known` as a stabiliser chain (`canon_symmetry_insert`: exact action check `x^g = x`, then `canon_bsgs_insert_verified`, so every generator of the chain is a checked automorphism and the chain is re-verified on every growth), the pointwise stabiliser `A_S` of a node's prefix by an unverified transient rebase of `A_known` (`canon_symmetry_stabiliser`: the prefix points become the first base points; level `d` generates `A_S`), the orbits of `A_S` on a target cell by breadth-first search over those generators with a Schreier tree (`canon_symmetry_cell_orbits`: the first cell point of each orbit, in cell order, is the representative), and the explicit transporter `a ∈ A_S` with `rep^a = b` read off the tree (`canon_symmetry_transporter`, the automorphism a certificate names for a pruned child). Sources of `A_known`: the input generators of `G` that fix `x` (source i, S7) and, from slice S7b (`docs/slices/S7b.md`), the implicit automorphisms `t_L t_best⁻¹` of leaves with the incumbent's key, verified by the group's membership test in the search and by exact action here; `canon_symmetry_cell_orbits` takes optional representative flags so that the search can mark the orbits of the already explored children under a grown `A_known` (the epoch counter tells it that `A_known` grew). Counters: candidates, inserted, rebases, orbits. Tests: `tests/c/test_symmetry.c` (T1 tier against brute force: `A_known` equals the closure of the fixing generators, every orbit representative and transporter checked for every prefix of every subgroup of `Sym(n)`, `n ≤ 4`, every subset).

**What may live here.** C17 sources and internal headers for this module only, no third-party code and no dependencies beyond the C standard library. Each rule implemented must cite its spec section in a comment (see `CLAUDE.md`). Golden constants must be derived from the rules, never copied (spec §20).
