# src/arena

**Purpose.** Admission-time allocation, live-memory ledger, bounded caches and workspace storage.

**Governing spec sections** (`docs/specification.md`, normative): §11 (capacity, rollback, all live memory), §12 (complexity ledger), §16 (exact caches).

**Status.** S1 adds `checked.h` (overflow-checked `size_t` multiplication and addition used before every allocation, spec §11.1) and `refcount.h` (atomic handle reference counts, spec §17 sharing; the count is reached through a pointer so const handles can be retained without a cast). S2 (review items 6 and 7) adds `canon_u64_add`/`canon_u64_mul` to `checked.h` (exact counts, multiplicities and stream lengths) and `alloc.h` with `canon_alloc_array`, the one checked array allocator (max(count, 1) elements; size overflow is `CAPACITY_LIMIT`, a failed `malloc` `RESOURCE_LIMIT`), used by the graph, root-image, refinement-scratch and search-state allocations. S3 adds `canon_grow_array`, the one growth helper of grow-only uint32-indexed arrays; S5 generalises it to `canon_grow_array_to` (grow to hold `need` elements while keeping `used`, so an arena can append several references at once, and with `used = 0` reserve scratch), and `canon_grow_array` is now that helper with `need = count + 1`. Slice S8 (`docs/slices/S8.md`) adds `mem.h`/`mem.c`, the one allocator of the library and the live-memory ledger of spec §11.2: every allocation in `src/` goes through `canon_mem_malloc`/`calloc`/`realloc`/`free` (each block carries its size; process-wide atomic live, peak, allocation, free and failure counters, read by the public `canon_memory_get`), `canon_mem_peak_reset` brackets a solve's high-water mark, and `canon_mem_fail_after(k)` injects an allocation failure for `tests/c/test_faults.c`. `canon_alloc_array` and `canon_grow_array_to` sit on top of it. The admission plan (spec §11.1) lives in `src/api/api.c` (`plan_bytes`); worker-local arenas and the strict memory fallback remain M5/M6.

**What may live here.** C17 sources and internal headers for this module only, no third-party code and no dependencies beyond the C standard library. Each rule implemented must cite its spec section in a comment (see `CLAUDE.md`). Golden constants must be derived from the rules, never copied (spec §20).
