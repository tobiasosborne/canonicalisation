# src/api

**Purpose.** Public entry points, handle lifecycle, status and result flags, wrappers.

**Governing spec sections** (`docs/specification.md`, normative): §17 (API, ownership, failures), §3.2 (status and flags), §3 (objectives).

**Status.** Implemented in S1: `api.c` (context and capacity descriptor, retain/release for group, object, problem, workspace and result, `canon_group_create` on the explicit backend, `canon_object_create_subset`, from S2 `canon_object_create_graph` (both colour arrays NULL means all colours empty) and `canon_object_create_simple_graph` (objects are `canon_root`s), `canon_problem_create` with its capacity argument (output size: exact subset or graph stream length), `canon_workspace_create`, `canon_solve` for `CANONICAL_IMAGE`/P1/CDAG-2/CDAG-BYTE-1, the result accessors and `canon_result_encode` with a sink), `version.c`, and `stubs.c` for the entry points of later slices (`canon_solve_batch` S8, checkpoints M6). Slice S3: the context is immutable and carries a group backend chosen at creation (`canon_context_create_with_options` with `canon_context_options`, default chain); `canon_group_create` dispatches on it (chain: `src/bsgs/chain_backend.c`, limited only by a `uint64` order; explicit: `max_group_order`), `canon_group_order` returns the exact order, and `canon_problem_create` asks the group's backend whether the descriptor admits it (`ops->admits`: explicit, order ≤ `max_group_order`; chain, always). Slice S4: `canon_problem_create_with_options` (a target object for the transporters, `canon_problem_options` with the witness mode; the supported objective/profile/order combinations, the §4.4 class check for `SIMPLE-UPPER-1`, a conservative `Group` output bound), `canon_solve` dispatching to the P1 search (plus the deterministic witness on request) or to `src/search/objectives.c`, results that own copies of the group payload and the order key and retain the problem's group and objects for `canon_result_verify_witness`, and the accessors `canon_result_group_bytes`, `canon_result_order_key`, `canon_result_transporter`. Slice S5: `canon_object_create` (stream import through `canon_root_import_stream`, with the context's limits of the normal form), `canon_stream_validate` (`canon_cdag_validate`), the capacity fields `max_nodes`, `max_refs`, `max_literal_bytes` with their defaults, and their check at problem creation for the object and the target (`canon_root_counts`); the output size of a nested object is exact without subgroup or coset leaves and the conservative bound of `canon_dag_image_bound` with them. All signatures are provisional until **M4**. Public declarations live in `include/canon/canon.h`.

**What may live here.** C17 sources and internal headers for this module only, no third-party code and no dependencies beyond the C standard library. Each rule implemented must cite its spec section in a comment (see `CLAUDE.md`). Golden constants must be derived from the rules, never copied (spec §20).
