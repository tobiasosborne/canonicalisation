# tests/python

**Purpose.** `unittest` tests for data and tools (no pytest, no pip installs).

**Run.** `nice -n 19 python3 -m unittest discover -s tests/python -q` from the repository root, after `make` (`test_e2e.py` needs the CLI: it reads `CANON_CLI`, else `build/make/canon-cli`; without a built CLI its tests skip with a message, unless `CANON_REQUIRE_CLI=1`, which `make check`, `ctest` and CI set, turns the skip into a failure).

**Tests.** `test_golden_vectors.py` recomputes each entry of `refs/vectors/golden.json` with `checks/review_checks.py` (P1 trace, stream and witness; group and coset payloads; convention vectors; signed and labeling examples). `test_hexdump_stream.py` parses the six spec §7.4 streams and malformed variants with `tools/hexdump_stream.py` (since the S5 review including overlapping rule-1 Group blocks). `test_e2e.py` (slice S1) runs `canon-cli` over every subgroup of `Sym(n)`, `n ≤ 4`, and every subset with two generating sets (full element list and greedy sequence), comparing trace, bytes and witness with `checks/review_checks.p1` and with each other, checks that the witness is the spec §3 deterministic witness, runs the subset entries of `golden.json`, and checks the §11.1 node quota, invalid input and usage errors. Slice S2 adds the graph tiers G1 (n ≤ 2, every subgroup, every multiplicity vector in {0,1,2}^(n·n), colours all empty and distinct) and G2 (n = 3, 4, every subgroup, 40 seeded random labelled, coloured multigraphs per group), each compared field by field with `review_checks.p1(..., "graph", ...)` under both generating sets, with the arcs shuffled and partly split into duplicates on the CLI side, every emitted stream parsed by `tools/hexdump_stream.py`; plus the §7.4 graph entry of `golden.json`, a graph whose leaves are partly skipped by the trace-first rule, a huge degree (`CAPACITY_LIMIT` for both subcommands), a graph node quota and `p1-graph` usage errors.

Slice S3: `CANON_BACKEND=chain|explicit` makes every CLI call of `test_e2e.py` pass `--backend`; `make check` and `ctest` (`test_e2e_explicit`) run the file again with the explicit backend, and both runs must agree with the model. The `Backends` class checks the option itself and a group of order 131072 that only the chain backend admits.

Slice S4: every record has seven fields (`group_hex` last). `test_e2e.py`'s `EnumerationObjectives` checks `LEX_MIN_IMAGE`, `TRANSPORTER_ONE`, `STABILISER`, `TRANSPORTER_COSET` (with both witness modes) and the deterministic witness of the canonical image against brute force with `review_checks` (`closure`, `mul`, `act_object`, `subset_bytes`, `graph_bytes`, `group_bytes`, `perm_bytes`) on the T1 subsets (every T1 group's `Group(G)` bytes through the stabiliser of the empty subset), the G1 digraphs and 30 random groups on `n ≤ 6` points with random subsets and digraphs, plus `SIMPLE-UPPER-1` minima on 40 random simple graphs; the witness of the `any` mode is pinned to the §8.1 traversal order by a Python model of the enumerator written from the spec; also the §7.4 minimum and payload cases, the quota boundaries, statuses and usage errors. `test_compare.py` runs `refs/compare/compare.py` on CLI records of both backends (agreement, a `group_hex` disagreement, rejection of six-field lines, planted corruption).

Slice S5: `test_e2e.py`'s `NestedObjects` (tier D1) feeds 280 random nested objects (tags 01-06, and since the S5 review subgroup and labeling-coset leaves 07 and 08 given by non-canonical presentations, canonicalised in the oracle by `review_checks.group_bytes`; `n ≤ 4`, depth ≤ 3, sharing, duplicate storage and unreachable records; every subgroup of `Sym(n)`) to `canon-cli p1-stream` as non-canonical streams and compares trace, bytes and witness with an oracle written in the test: a normaliser and encoder for tags 01-06 (extending the idea of `review_checks.dag_bytes`), the action with `g⁻¹pg`, and the P1 tree of the empty-key root returning every leaf; it checks the oracle against `review_checks.p1` on the empty subset and against `review_checks.dag_bytes`, the §7.4 DAG entry of `golden.json` with shared and duplicated storage, that every canonical output passes `canon-cli validate` and `tools/hexdump_stream.py` and that a raw input validates iff it is its own normal form, the enumeration objectives on a third of the D1 objects against brute force, the hexdump rule list (refused by the tool, by `validate`, and by import where the spec makes the stream malformed), and the stream statuses and usage errors. Both backends run it (`make check`, ctest `test_e2e_explicit`).

Slice S6: `test_e2e.py`'s `LabelingAndSigned` runs tier L1 (`canon-cli labeling` for every ρ ∈ `Sym(n)` on the T1 subsets and the G1 digraphs: `λ ∈ Gρ`, c, trace and t equal `review_checks.p1` on `(x^ρ, ρ⁻¹Gρ)`, the payload equals `group_bytes(A) + perm_bytes(min(Aλ))`, `Aλ` is the set of labelings taking x to c, representative change and coordinate rename as in `review_checks.run_v2`) and tier Z1 (`canon-cli signed` for every sign vector on the greedy generators of every T1 group: non-characters `INVALID_INPUT`; for every character, cross-checked with `review_checks.characters` where `|G| ≤ 12`, and every subset or G1 digraph: zero iff an odd stabiliser element exists, with the exact certificate, a nonzero sign `χ(t)` with the unsigned P1 image and `group_bytes(A)`, covariance, the cross-feed `s(C(x)) = +1`), plus the §7.4 labeling and signed cases, quota and usage errors; every canonical output passes `canon-cli validate` and the hexdump tool. Both backends run it.

**Fast mode (S6 review item 8).** `CANON_E2E_FAST=1` runs the large tiers of `test_e2e.py` on seeded subsets, so that the sanitizer build stays quick; CMake sets it for `test_e2e` and `test_e2e_explicit` exactly when `CANON_SANITIZE` is ON, and `make check` (no sanitizers) runs every tier in full. The subsets are fixed by the case numbers and seeds:
- S2 G2: 12 graphs per group instead of 40.
- S4: a quarter of the T1 subsets (always the empty set, so every T1 group's `Group(G)` bytes are still checked), a quarter of the G1 digraphs, 8 random groups instead of 30.
- S5 D1: a third of the random objects.
- S6 L1: on the T1 subsets, every ρ for `n ≤ 3` with the representative change and rename on the first ρ, and one seeded ρ for every other subset at `n = 4`; on the G1 digraphs, a third of the cases.
- S6 Z1: covariance over two seeded `h` for `n ≤ 3` and one for `n = 4`, with every other subset at `n = 4`; a third of the G1 digraph cases.

The S1 T1 subsets, the S2 G1 digraphs, the golden cases, the quotas and the status and usage checks always run in full. Measured against the ASan/UBSan CLI: one fast run of `test_e2e.py` takes about 108 s, against about 436 s in full.

**Governing spec sections.** §7.4 (golden cases), §4.1 (wire grammar), §4.2 (normalisation), §9.4 (Group payload), §8 (enumeration objectives), §3.1 and §8.4 (labeling cosets, signed images), §20.
