# Planted-corruption runs (detailed plan WP0.7), 13 October 2026

Spec §20: "Plant an action/sign/encoding corruption and show the comparison catches it."  Three
switches were implemented in the production path for this purpose only, read from the environment
variable `CANON_PLANT`, a separate `canon-cli` was built from them (`build/plant`), ref-a
(`refs/ref-a/run_cases.py`) was run clean and planted on the same case files, and
`refs/compare/compare.py` compared the two record files.  The switches were deleted before the
seal (`refs/SEALS.md`); the logs below are retained.

| Switch | Corruption | Case file | Records | `DISAGREE` | Log |
|---|---|---|---|---|---|
| `sign` | χ negated on the first generator in `canon_group_create_signed` | every 20th case of `tools/gen_cases.py --tier T1 --seed 20261013` (1 557 cases, every objective) | 1 557 | 588 | `T1-every20-sign.log` |
| `action` | the P1 leaf image computed with `t⁻¹` instead of `t` (composition on the wrong side) | same | 1 557 | 110 | `T1-every20-action.log` |
| `encoding` | the §4.2 height ordering omitted when numbering a normalised DAG | same | 1 557 | 0 | `T1-every20-encoding.log` |
| `encoding` | same switch | `tools/gen_cases.py --tier T2 --seed 20261013 --count 20` (846 cases) | 846 | 10 | `T2-seed20261013-count20-encoding.log` |

**Reading of the `encoding` row.** WP0.7 asks each switch to produce a disagreement on T1.  T1
(WP0.6) holds subsets, atom tuples and digraphs: their canonical streams have at most two heights
(atoms, then one container) and the interning order already lists the atoms first, so omitting
the height sort cannot change a T1 stream.  The switch is exercised by the nested objects of T2
(depth ≤ 4 with sharing), where it changes 10 records (canonical images, minima and labelings of
DAG objects).  The T2 run is therefore the evidence for this switch; T1 carries no nested object
by design.

**Commands** (from the repository root; the case files are regenerated by the seeds):

```sh
python3 tools/gen_cases.py --tier T1 --seed 20261013 --out /tmp/T1.json   # then every 20th case
python3 tools/gen_cases.py --tier T2 --seed 20261013 --count 20 --out /tmp/T2.json
python3 refs/ref-a/run_cases.py /tmp/T1-every20.json --cli build/make/canon-cli --out clean.tsv
CANON_PLANT=sign python3 refs/ref-a/run_cases.py /tmp/T1-every20.json --cli build/plant/canon-cli --out sign.tsv
python3 refs/compare/compare.py clean.tsv sign.tsv > T1-every20-sign.log
```

A control run with `CANON_PLANT=none` on the planted binary agreed on all 1 557 records, so the
disagreements come from the switches, not from the second build.  Toolchain: gcc 13.3.0, Python
3.13.16, Linux x86-64.
