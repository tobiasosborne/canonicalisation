## Spec readings taken

1. **The header's third byte (§4.1).** "43 4e 02 | U16(schema=1) | U16(action=1) | ..." and "unknown schema/action/profile/encoding versions are unsupported, never reinterpreted". The first two bytes are read as the magic (anything else is `INVALID_INPUT`, not a CDAG stream) and the third as the encoding version (CDAG-2 is encoding ID `0x0002`): a stream `43 4e 03 …` is `UNSUPPORTED_ACTION`. `tools/hexdump_stream.py` calls all three bytes "magic" and reports "bad magic/version"; both reject.
2. **Import versus canonical streams (§4.1, §4.2).** §4.1 states the grammar ("Every child reference is a U32 index smaller than the parent index", "k increasing distinct child references", `Perm` rules, "no padding or trailing bytes") and also "all records are reachable from root"; §4.2 says "Source sharing, unreachable allocation records and insertion order have no meaning. Discard unreachable input nodes". Read together:
   - import (`canon_object_create`) enforces the grammar of every record strictly, but accepts unreachable records, a root other than the last record, repeated equal records, and any well-formed `Group` presentation or coset representative (they are presentations of the same value, recomputed by §9.4);
   - `canon_stream_validate` additionally requires byte identity with the normal form, so all of those are rejected there ("repeated equal nodes, redundant references, leading zeroes, noncanonical orders or unreachable records are invalid canonical encodings").
3. **Duplicate and unsorted arcs (brief §3.5 decision).** §4.1: "Combine duplicate (source,target,label) arcs by exact addition, delete none with positive multiplicity, and sort by (source,target,B(label))". **Decided:** on import, arcs may come in any order and repeat; they are combined and sorted exactly as the S2 builder does (`canon_graph_init`). In `canon_stream_validate` they are rejected, because the canonical form has them combined and sorted, so re-encoding changes the bytes. This differs deliberately from set children, which §4.1's grammar itself requires to be "increasing distinct" and which are therefore rejected on import too. `test_cdag_decode.c` and the e2e malformed list check both sides; the hexdump tool rejects such arcs (it checks canonical streams).
4. **Graph records (brief §1, §3.1).** A graph record that is the root becomes the S2 graph object. A reachable graph record below the root is `UNSUPPORTED_ACTION` (a later slice; §2.1 "A recognised but unavailable type returns UNSUPPORTED_ACTION"). An unreachable graph record is only discarded on import, and makes the stream non-canonical for the validator (`UNREACHABLE`).
5. **The relations record `0a`** is `UNSUPPORTED_ACTION` as soon as the decoder reaches it; its payload is not parsed. **Status precedence:** the first violation in stream order decides (a malformed record after a `0a` record still gives `UNSUPPORTED_ACTION`); then the normaliser (nested graph, multiset count overflow, group order); then the limits of the normal form. Before the stream: NULL arguments, the schema/action arguments, the degree against `max_n`. The spec fixes no order.
6. **Group payloads (§9.4, §4.1).** Rule-1 blocks must have size ≥ 2, increasing points, blocks ordered by least point, and must be pairwise disjoint (§9.4: they are "the H-orbits", "Omit singleton orbits"); overlapping blocks are `INVALID_INPUT`. A rule-1 payload presents the product of the symmetric groups on its blocks, generated per block by the transposition of its first two points and the cycle through all of them. A subgroup or coset leaf whose group order exceeds `uint64` is `CAPACITY_LIMIT` (the S3/S4 order limit).
7. **Counts (§4.1, §11.1, detailed plan §2.1).** A multiset count or arc multiplicity `Nat` with a leading zero byte is `INVALID_INPUT`, zero is `INVALID_INPUT`, and a shortest form longer than 8 bytes (a number ≥ 2^64) is `CAPACITY_LIMIT` (count-bit limit 64). Merging equal multiset children adds counts with overflow → `CAPACITY_LIMIT`.
8. **Heights (§4.2).** "height 0 if it has no child references": an empty tuple, set or multiset has height 0 and sorts among the leaves by its record bytes (tag first).
9. **"Equal records are one node" (§4.2) at the numbering stage.** Interning has already merged equal values, and distinct interned nodes have distinct records (a differing tag, payload or child identity; the final indices are a bijection of the interned ids), so two equal records within a height cannot occur. The normaliser checks this and returns `INTERNAL_ERROR` instead of merging (brief §3.2 step 3 says "merge"; merging there would also require re-deduplicating the parents' children, which is unreachable).
10. **Record order without materialising bytes (§4.2, §4.3).** Within a height, records are sorted by a field-wise comparator: the tag, then a leaf's payload bytes (a leaf's record is tag ‖ payload), or `U32(k)`, the child indices and (multisets) each `Nat(count)`. Fixed-width big-endian fields compare as numbers and a shortest `Nat` compares as its number, so the first differing field decides exactly as the first differing byte. The justification is in `record_cmp` (`dag.c`); the D1 oracle sorts real bytes and agrees on every case.
11. **Acyclicity (§4.2 "bounded explicit traversal").** The arena requires every child to precede its parent (`canon_dag_append` refuses anything else, and the decoder checks §4.1's rule), so one pass over the references verifies acyclicity; reachability is one descending pass from the root. No programmatic arena builder is public in S5, so the brief's DFS for arbitrary arenas is not needed.
12. **Root kinds (§7.1, brief §3.4).** After normalisation, a root that is a set whose children are all atoms (including the empty set) is a subset; a graph record is a graph; every other root (atoms, literals, tuples, multisets, sets with a non-atom child, permutation, subgroup and coset leaves) has the empty initial key and empty O signatures, so its P1 tree is the empty subset's tree. `test_search_dag.c` checks the trace equality and that subsets and graphs imported from non-canonical streams give the builders' trace, bytes and witness on every T1 group.
13. **The action on leaves (§2.1).** A permutation leaf `p` becomes `g⁻¹pg`, i.e. `q[g[v]] = g[p[v]]`: the cycles of `p` relabelled through `g`. This is the transport that keeps "p maps a to b" equivalent to "q maps g[a] to g[b]" for atoms moved by ATOM-TRANSPORT-1, and §7.4's "(0,2)^(pq)=(2,1)" read as a cycle (golden-corpus reading). A subgroup leaf conjugates its generators; a coset `H r` becomes `(g⁻¹Hg)(g⁻¹r)` with `(g⁻¹r)[g[v]] = r[v]`; both payloads are recomputed by the S4 writers from a verified chain.
14. **Capacity (§11.1, detailed plan §2.1).** "Validation is deterministic over the normalised input": `max_nodes`, `max_refs` and `max_literal_bytes` are compared with the normal form's records, child references and Σ|s| over literal records, never with the raw stream (a stream with many repeated records whose normal form fits is admitted; tested). Decoding memory is bounded by the stream length itself (every count is checked against the remaining bytes before any allocation). At problem creation the object and the target are checked against the resolved descriptor; a builder's subset of `k` atoms counts `k + 1` records and `k` references, a graph one record; graph colours and labels are not literal records (`max_output_bytes` covers them).
15. **Targets of another kind.** The S4 rule "the target must have the object's kind" still applies; with streams the kind is the detected root kind, which is invariant under the action, so a kind mismatch means the target is not in the orbit. It stays `INVALID_INPUT` (not an exhausted empty answer), as in S4.

## The output-size argument (brief §3.6 decision)

The brief says: "the stream length is invariant because each record's length is unchanged by relabelling and re-sorting; argue this in a comment and test it on random DAGs ... if the argument fails for some record type, fall back to the conservative input-derived bound and say so in the notes."

- **Tags 01–06: exact.** The action maps the normalised records one to one (it is a bijection on values, so no two records merge and none split), and each record keeps its length: an atom is 5 bytes; a literal is fixed; a tuple or set keeps `k` (a set's `k` distinct children have `k` distinct images); a multiset keeps its counts and hence its `Nat` lengths; `Perm(g⁻¹pg)` lists as many moved points as `Perm(p)` (conjugation preserves the support size). Re-sorting only permutes records and children. So every image has the stream length of `x`, which is the exact output size. `test_dag.c` checks it on 300 random DAGs with four random `g` each.
- **Tags 07 and 08: the argument fails.** The canonical `Group(H)` payload of a conjugate can be longer or shorter than that of `H`, because rule 2's greedy sequence depends on the numbering of the points. Concrete case: `C4 = ⟨(0 2 1 3)⟩ = {id, [1,0,3,2], [2,3,1,0], [3,2,0,1]}` on 4 points has least non-identity element `[1,0,3,2]`, which generates only half of it, so its sequence has two generators (payload 77 bytes); conjugated by `g = (1 2) = [0,2,1,3]` it becomes `⟨(0 1 2 3)⟩`, whose least element `[1,2,3,0]` generates it (41 bytes). A brute-force scan over every subgroup `H` of `Sym(4)` and every conjugator `g` finds 64 pairs `(H, g)` with differing lengths, and 1240 among 86 sampled subgroups of `Sym(5)`. The coset representative `Perm(r₀)` likewise varies.
- **Fallback, implemented.** For a nested object with subgroup or coset leaves, the output size is the input's stream length with each `Group` payload replaced by the §9.4 bound for its order (`canon_group_bytes_bound`: rule 1 at most `5 + 4⌊n/2⌋ + 4n`, rule 2 at most `⌊log₂|H|⌋` permutations of `4 + 8n` bytes) and each coset's `Perm(r₀)` by `4 + 8n`. `|g⁻¹Hg| = |H|`, so the bound is the same for every element of the orbit, as §11.1 requires ("An API promising this property may conservatively reject an instance with a smaller actual output"). `canon_dag_image_bound` computes it at import (one verified chain per such leaf); `test_dag.c` checks the C4 case (77 and 41 bytes, the same bound for both) and `test_search_dag.c` the boundary through the API (96 bytes refused, 97 admitted; the canonical image under `Sym(4)` is 61 or 97 bytes).

## Deviations from the brief and why

- **`canon_rec.payload_off` and `payload_len` are `size_t`**, not `uint32`: a literal's payload `B(s)` alone can exceed `2^32 − 1` bytes (§4.1 allows `|s|` up to `U32`), and the pool is a `canon_buf`.
- **`canon_grow_array_to` in `src/arena/alloc.h`.** An arena appends `k` references at once; `canon_grow_array` (make `cap > count`, copy `count`) cannot grow to `refs + k` without reading past the old block. The helper now has a general form (grow to `need`, keep `used`), and `canon_grow_array` is that form with `need = count + 1`, so there is still exactly one growth implementation. Scratch is reserved through it with `used = 0`.
- **`src/encoding/cdag_encode.h`** exists besides `cdag_encode.c` (the brief lists only the `.c`).
- **The decoder takes the expected degree and `max_n`**, so a degree mismatch or an oversized `n` is reported from the header, before any record is read.
- **`canon-cli validate`** is new: the e2e tier has to run `canon_stream_validate` on every output. It prints `CASE<TAB>STATUS`, which is not a FORMAT.md record.
- **The S1–S4 tests changed only mechanically.** Adding three fields to `canon_capacity` makes `-Wmissing-field-initializers` (part of `-Wextra -Werror`) reject the positional initialisers such as `{0, 0, 2, 0}`. Fifteen initialisers and compound literals in `test_chain.c` (1), `test_group_explicit.c` (1), `test_objectives.c` (3), `test_search_graph.c` (4) and `test_search_subset.c` (6), and one in `canon-cli.c`, gained `, 0, 0, 0`; a zero selects the default, so no test changed meaning. `test_version.c` no longer expects `canon_object_create` to be a stub and checks its NULL-argument behaviour and `canon_stream_validate`'s.
- **The pinning pair of brief §3.3** is kept, and a second one added (see the conflicts).
- **Numbering-stage merge** is an `INTERNAL_ERROR` check, not a merge (reading 9).
- **D1 composition.** 280 objects: 10 per group for `n ≤ 3` (10 groups), 6 per group for `n = 4` (30 groups); per object one `p1-stream` run with the greedy generators (plus the full element list on the first object of each group), `validate` on the output and on the raw input, and on every third object `min` (deterministic), `stabiliser` and `transporter-coset` (deterministic) against brute force. Of the 280, 22 normalise to subsets (subset path) and 76 raw inputs happen to be canonical already (so `validate` sees both outcomes); the normal forms have 4.6 records on average and up to 20. Both backends run the tier.

## Suspected conflicts (spec, brief, model)

1. **Brief §3.6, output size.** "the stream length is invariant because each record's length is unchanged by relabelling and re-sorting". False for subgroup and labeling-coset leaves: `C4 = ⟨(0 2 1 3)⟩` on 4 points has a 77-byte canonical `Group` payload and its conjugate by `(1 2)` a 41-byte one (above). Implemented: exact size for tags 01–06, the conservative bound otherwise, as the brief's fallback allows. Suggest stating in the brief (and in a comment near §9.4's size proof) that `Group` and coset payload lengths are not conjugation-invariant.
2. **Brief §3.3, the pinning pair.** "Pin the conjugation side by a test with p = [1,0,2], g = [0,2,1]: g⁻¹ p g must equal ... [2,1,0]". `g = [0,2,1]` is an involution, so `g⁻¹pg = gpg⁻¹ = [2,1,0]` and the test cannot detect the wrong side, although `p` and `g` do not commute. `test_dag_action.c` keeps the pair and adds `g = [1,2,0]` (order 3): `g⁻¹pg = [0,2,1]` (the cycle (0 1) relabelled 0 → 1, 1 → 2), while `gpg⁻¹ = [2,1,0]`; a mutation of `dag.c` to the other side fails 654 checks. Suggest a `g` of order 3 in the brief and in detailed plan WP3.6.
3. **`tools/hexdump_stream.py` and rule-1 blocks.** The tool checks that each block is increasing and that blocks are ordered by least point, but not that blocks are disjoint, so it accepts `01 00000002 | 00000002 00000000 00000001 | 00000002 00000001 00000002` (blocks {0,1} and {1,2}), which is not a set of orbits (§9.4). The C decoder rejects it. The tool was not changed (it is the reference rule list); the e2e malformed list contains only streams both reject.
4. **Spec versus model.** No disagreement between the specification and `checks/review_checks.py` was found in the S5 scope. Evidence: the D1 oracle reproduces `review_checks.p1` on the empty subset for every T1 group and `review_checks.dag_bytes` on its tag 1–4 cases (the §7.4 pair with shared and duplicated storage, the review's insertion-order case, the depth-60 chain); every D1 case agrees byte for byte with the C path under both backends; the §7.4 DAG entry of `golden.json` matches from shared and from duplicated storage. `review_checks.dag_bytes` accepts a set listed as `(0, 1, 0)` (a repeated reference), which is not wire syntax; it is a model convenience, not a disagreement.

## Left out (later slices)

- The relations record `0a` and graph records below the root (`UNSUPPORTED_ACTION`); auxiliary-vertex profiles (§6); labeling-coset objectives (S6); pruning (S7); `canon_nat` beyond `uint64` (as in S4).
- A public programmatic builder for nested objects: S5 imports them from streams only.
- Performance: the image of a subgroup or coset leaf rebuilds and verifies a chain per P1 leaf and per enumeration leaf (the S3/S4 cost model; M5). The normaliser clears its hash table per call (at least 16 slots). Import allocates its own scratch per call.
- Decoder fuzzing in CI (detailed plan WP3.3: from M4 onwards); `test_cdag_decode.c` runs 3000 random bit flips under the sanitizer builds.
