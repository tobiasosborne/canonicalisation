# Slice S5: nested objects, extensional normalisation, CDAG-2 decoder and validator

**Goal.** Objects of schema `EXT-DAG-1` can be imported from a CDAG-2 stream, normalised extensionally, canonicalised under P1 and re-encoded, with sharing preserved. The decoder is strict; a canonical-form validator reconstructs the normal form and requires byte identity. Nested tuples, sets, multisets, literals, atoms and permutation, subgroup and labeling-coset leaves are supported. `canon_object_create` from a stream is implemented.

Normative text: `docs/specification.md` v2.0 (cited §x): §§2.1, 4.1, 4.2, 4.3, 7.1, 7.2, 9.4, 11.1, 17. Process: `docs/detailed-implementation-plan.md` §0, §0a, §2.1, §2.5, §6 (WP3.2, WP3.3, WP3.6). Prerequisites: S1–S4 landed (S4 supplies `Group(H)` and `Perm` writers and the chain for group leaves). The S1 §2 rules and the conventions enforced in the S1–S4 reviews apply.

## 1. Scope

In scope:

- `src/object/dag.{h,c}`: the record arena, bounded acyclicity validation, discard of unreachable records, bottom-up extensional normalisation and canonical height numbering (§4.2), the root-kind detection (§7.1), action by `ATOM-TRANSPORT-1` (§2.1) with re-normalisation, exact equality.
- `src/encoding/cdag_decode.{h,c}`: strict parser of the §4.1 grammar for tags `01`–`09` into a record arena; `canon_stream_validate` for canonical streams (§4.2).
- `src/encoding/cdag_encode.c`: the general encoder from a normalised arena (the subset and graph specialisations of S1/S2 must produce identical bytes and are kept as fast paths with a test asserting identity).
- Root dispatch (`src/object/object.h`): a third root kind `CANON_ROOT_DAG`, with the subset and graph kinds detected from a decoded stream so that existing paths are reused.
- `src/api/`: `canon_object_create` (stream import), `canon_stream_validate`, capacity fields `max_nodes`, `max_refs`, `max_literal_bytes` (detailed plan §2.1).
- `tools/canon-cli.c`: subcommand `p1-stream --stream HEX` (and the S4 objectives accepting `--stream` for the object and target).
- Tests: C unit tests; Python e2e tier for DAG roots with a small Python oracle; decoder rejection tests derived from the hexdump tool's rule list.
- READMEs; `docs/slices/S5-notes.md`.

Out of scope: the relations record `0a` (a later slice; the decoder reports `UNSUPPORTED_ACTION` for it), graph records nested below the root (likewise `UNSUPPORTED_ACTION`), schema/action IDs other than `1/1` (`UNSUPPORTED_ACTION`, §4.1), auxiliary-vertex profiles (§6), labeling-coset objectives (S6), pruning (S7), `canon_nat` beyond `uint64` multiplicities (deferred as in S4).

## 3. Design

### 3.1 Record arena (`src/object/dag.h`)

```c
typedef struct canon_rec {
    uint8_t tag;                /* 0x01..0x09 */
    uint32_t child_count;       /* tuple/set/multiset: children; others 0 */
    uint32_t child_off;         /* offset into the arena's child-id array */
    uint32_t payload_off, payload_len;  /* literal bytes; perm/group/coset/graph: their
                                           canonical payload bytes; atom: 4-byte id */
    uint32_t height;
} canon_rec;
```

Children of a multiset carry a `uint64_t` multiplicity in a parallel array (overflow of a merged count → `CAPACITY_LIMIT`, §11.1 count-bit decision). Permutation, subgroup and labeling-coset records store their **canonical payload bytes** (`Perm(p)` per §4.1; `Group(H)` and `Group(H) || Perm(r₀)` per §9.4, computed with the S4 writers from a chain built for the leaf) so that extensional equality of group leaves is byte equality of canonical payloads (§4.2: "This proof assumes exact equality/normal forms for group leaves"). A graph record at the root is handed to the S2 graph object; a graph record elsewhere is `UNSUPPORTED_ACTION` in S5.

### 3.2 Normalisation (`dag.c`) (§4.2)

1. **Acyclicity and reachability.** Child references must be smaller indices in a decoded stream (§4.1), which makes an imported stream acyclic by construction; a programmatic arena may be checked by a bounded DFS with an explicit stack. Mark records reachable from the root; discard the rest.
2. **Bottom-up interning.** Process records in increasing height. For each reachable record compute its normalised form: atoms and literals as is; tuples with children replaced by their canonical ids; sets with children replaced, sorted by id, duplicates removed; multisets with children replaced, sorted by id, equal children merged by adding counts (overflow → `CAPACITY_LIMIT`). Intern by exact `(tag, payload, child ids, counts)`; equal forms are one node.
3. **Height numbering.** Height 0 for records with no child references (atoms, literals, perm/group/coset payloads, graph records), else `1 + max child height`. Number nodes by increasing height; within a height sort by the exact record bytes (computed with the already assigned child indices) using the shared stable sort, and merge records whose bytes are equal. The root is the last record (every proper descendant has smaller height).
4. **Invariant test.** Re-normalising a normalised arena yields the identical arena; encoding then decoding then normalising yields identical bytes.

### 3.3 Action and leaf evaluation (§2.1, §7.2)

`ATOM-TRANSPORT-1` on an arena: atom `a ↦ g[a]`; literal fixed; tuple positions preserved; sets and multisets relabelled then re-normalised (their child order can change); a permutation leaf `p ↦ g⁻¹ p g`; a subgroup leaf `H ↦ g⁻¹ H g` by conjugating its generators and recomputing the canonical payload; a labeling coset `H r ↦ (g⁻¹ H g)(g⁻¹ r)`. The image's normalised arena is encoded to the leaf bytes. Pin the conjugation side by a test with `p = [1,0,2]`, `g = [0,2,1]`: `g⁻¹ p g` must equal the array obtained by relabelling the cycle `(0 1)` through `g`, i.e. the cycle `(0 2)`, which is `[2,1,0]`; check the convention against spec §2.1 ("A permutation object p becomes g⁻¹pg") and §7.4's cycle vector.

### 3.4 Root-kind detection (§7.1)

After normalisation: if the root is a set whose children are all atoms (including the empty set), the root is a **subset** and S1's path applies (initial key = membership); if the root is a graph record, S2's path applies; otherwise the root is a **DAG** with the empty initial key, an O stage with empty signatures and the G stage of S1. Assert by test that a subset imported from a stream and a subset built by `canon_object_create_subset` give identical trace, bytes and witness; likewise for graphs.

### 3.5 Decoder and validator (`cdag_decode.c`) (§4.1, §4.2)

Strict parse: header `43 4e 02`, `U16(schema)`, `U16(action)`, `U32(n)`, `U32(q ≥ 1)`, `q` records, `U32(root < q)`, no trailing bytes. Per tag the payload grammar of §4.1 with: child references smaller than the parent index; set children strictly increasing; multiset children strictly increasing with positive `Nat` counts in shortest form; `Perm` with increasing sources, no fixed pairs, in-range targets, bijective on its support; `Group` rule-1 blocks with increasing points and blocks ordered by least point, or rule-2 generator sequences; coset `Group || Perm`; graph records exactly as S2 imports them (and the §4.1 rule that duplicate `(source, target, label)` arcs are invalid in a canonical stream but combined on import — decide: on import combine; in `canon_stream_validate` reject, since the canonical form has them combined). Every violation is `INVALID_INPUT` with a reason enum for tests. Reachability of all records from the root is required by §4.1 ("all records are reachable from root") in a **canonical** stream; on import unreachable records are discarded (§4.2). `canon_stream_validate`: decode, normalise, encode, compare bytes.

Mirror `tools/hexdump_stream.py`'s rule list in `tests/c/test_cdag_decode.c` and add a Python test that feeds the same malformed streams to both the tool and the CLI and requires both to reject.

### 3.6 Capacity (§11.1)

At import check `nodes ≤ max_nodes`, `references ≤ max_refs`, `literal bytes ≤ max_literal_bytes` against the context defaults, and at problem creation against the problem descriptor. The output size of a DAG root is **not** invariant under the action in general (child orders change but record bytes keep their lengths; the stream length is invariant because each record's length is unchanged by relabelling and re-sorting; argue this in a comment and test it on random DAGs), so the exact-size check of §11.1 still applies; if the argument fails for some record type, fall back to the conservative input-derived bound and say so in the notes.

## 4. Tests

- C: `test_dag.c` (interning, dedupe, multiset merge, unreachable discard, height numbering, the §7.4 `(b,b)` case and the depth-60 chain with 61 records, sets of sets, insertion-order independence), `test_cdag_decode.c` (every rejection rule; round trips; `canon_stream_validate` accepts canonical streams and rejects a re-ordered but equivalent stream), `test_dag_action.c` (conjugation convention; relabelling of nested sets changes child order and re-normalises; group-leaf conjugation gives presentation-independent payloads), `test_search_dag.c` (P1 on DAG roots through the API; subset-from-stream equals subset-from-builder; graph-from-stream equals graph-from-builder).
- Python `test_e2e.py`, new tier **D1**: random DAGs over `n ≤ 4` atoms (depth ≤ 3, tags 01–06, literals from a two-element alphabet, sharing introduced deliberately), every subgroup of `Sym(n)`, both backends. Oracle, written in the test file using `review_checks` helpers: the tree of a DAG root is the tree of the empty-key root, so the trace set is that of `review_checks.p1(n, group, "subset", frozenset())`'s traversal; implement a small Python P1 for the empty-key root that returns every leaf `(trace, t)` (copy the structure of `review_checks.p1`, not its code), a Python `ATOM-TRANSPORT-1` on the random DAG (tags 01–06), and a Python normaliser/encoder for tags 01–06 extending the idea of `review_checks.dag_bytes` (that function covers tags 1–4 only; write the test's own for 5 and 6). The expected answer is the minimum `(trace, bytes)` over leaves with the least `t` attaining it. Also assert `canon_stream_validate` accepts every canonical output and the hexdump tool parses it.
