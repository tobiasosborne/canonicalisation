# Slice S1: subset canonical image, end to end

**Goal.** A caller can build a small permutation group and a subset through the public C API, request the P1 canonical image, and receive the complete trace, the CDAG-2 bytes, a valid witness, the status and the evidence flags. The same path is exposed by `tools/canon-cli` and agrees with the Python model over every subgroup of `Sym(n)` for `n ≤ 4` and every subset.

Normative text: `docs/specification.md` v2.0, cited as §x below. Process: `docs/detailed-implementation-plan.md` §0 and §0a. Everything in this brief is the slice's scope; nothing outside it is to be built in S1.

## 1. Scope

In scope:

- `src/perm/`: dense permutation primitives.
- `src/bsgs/`: a **group interface** plus an **explicit-enumeration backend** (the whole group as a sorted element table, bounded by a capacity). S3 replaces the backend behind the same interface.
- `src/object/`: the subset object.
- `src/encoding/`: wire primitives (`U16`, `U32`, `B`) and the CDAG-2 stream for a subset (header, atom records, set record, root).
- `src/partition/`: ordered partition with `split` and rollback.
- `src/refine/`: P1 initial key for a subset root, the O stage for a non-graph root (empty signatures), the G stage.
- `src/search/`: the unpruned P1 tree, trace bytes, leaf map, `(trace, bytes)` minimum, witness.
- `src/api/`: context, capacity descriptor, handles with retain/release, subset builder, problem, workspace, solve, result accessors, `result_encode` with a sink.
- `tools/canon-cli.c`: command-line driver emitting `refs/compare/FORMAT.md` records.
- Tests: C unit tests per module, a C end-to-end test on the §7.4 subset cases, and `tests/python/test_e2e.py` driving the CLI against `checks/review_checks.py` and `refs/vectors/golden.json`.
- Build: `Makefile` and `CMakeLists.txt` updated; CI unchanged in shape and green.

Out of scope (later slices): graphs and the O stage counts (S2), stabiliser chains (S3), every objective other than `CANONICAL_IMAGE` (S4, S6), CDAG-2 decoding and nested objects (S5), pruning and certificates (S7), memory ledgers, `solve_batch`, sink pause/resume, checkpoints (S8). Entry points for those remain stubs returning `CANON_UNSUPPORTED_ACTION`.

## 3. Public API additions (`include/canon/canon.h`)

All signatures remain **provisional until M4** and are marked so. Add:

```c
/* spec 11.1: problem-time capacity descriptor. Zero means "use the context default". */
typedef struct canon_capacity {
    uint32_t max_n;             /* degree admitted */
    uint64_t max_group_order;   /* S1 explicit backend: largest |G| that may be enumerated */
    uint64_t max_search_nodes;  /* spec 11.1 logical work quota: NODE tokens in the reference traversal */
    uint64_t max_output_bytes;  /* canonical stream bytes */
} canon_capacity;

canon_status canon_context_create(const canon_capacity *defaults, canon_context **out);
void         canon_context_release(canon_context *ctx);

/* retain/release for group, object, problem, workspace, result (spec 17: opaque handles;
 * releasing a failed or partial handle is always valid; release of NULL is a no-op) */
void canon_group_retain(canon_group *);      void canon_group_release(canon_group *);
/* ... same for object, problem, workspace, result */

/* spec 17 input builder (copies data): a subset of atoms of {0..n-1}; duplicates permitted
 * and deduplicated (spec 4.2: sets deduplicate equal children); out-of-range -> INVALID_INPUT. */
canon_status canon_object_create_subset(canon_context *ctx, uint32_t degree,
                                        const uint32_t *atoms, size_t count, canon_object **out);

/* result accessors (spec 3.2): */
canon_status             canon_result_status(const canon_result *);
canon_result_flags       canon_result_get_flags(const canon_result *);
/* spec 7.2 complete trace bytes; NULL/0 if not produced */
const uint8_t *canon_result_trace(const canon_result *, size_t *length);
/* spec 3 witness as an image array of length degree; NULL if not produced */
const uint32_t *canon_result_witness(const canon_result *, uint32_t *degree);
/* spec 4.3 canonical bytes, only when image_canonical && encoding_complete; else NULL/0 */
const uint8_t *canon_result_bytes(const canon_result *, size_t *length);
```

Change `canon_problem_create` to take `const canon_capacity *capacity` after `order` (NULL means the context defaults). `canon_group_create` builds the explicit backend; it returns `CANON_CAPACITY_LIMIT` when the closure would exceed `max_group_order` (checked before each growth of the table, never after). `canon_result_encode` streams the canonical bytes to the sink in one or more chunks; sink return `0` continues, any other value is a failure returning `CANON_OUTPUT_ERROR` with the result unchanged. Pause/resume (`1`) is **deferred to S8**: document that in the header comment and treat `1` as failure for now.

Status rules (§3.2): `canon_solve` returns `CANON_COMPLETE` with `witness_valid`, `image_canonical`, `encoding_complete` true and all other flags false; `CANON_CAPACITY_LIMIT` when `max_search_nodes` is exceeded (the result then has no trace, no bytes, no witness and all flags false); `CANON_INVALID_INPUT` for a degree mismatch between group and object; `CANON_UNSUPPORTED_ACTION` for any objective other than `0x0001`, any profile other than P1, any encoding other than CDAG-2, or any order other than CDAG-BYTE-1.

Context defaults when `defaults` is NULL: `max_n = 4096`, `max_group_order = 1 << 16`, `max_search_nodes = 1 << 20`, `max_output_bytes = 1 << 26`.

## 4. Internal design

### 4.1 `src/perm/` (spec §3)

Implement the two declared functions and add `canon_perm_apply_tuple(p, tuple, len, out)` (`out[i] = p[tuple[i]]`), `canon_perm_lex_compare(a, b, n)`, `canon_perm_is_identity`, `canon_perm_validate(p, n)` (bijection, range). Tests: the §7.4 convention vectors; `compose(p, inverse(p)) = id`; `inverse(compose(p,q)) = compose(inverse(q), inverse(p))` on random permutations.

### 4.2 `src/bsgs/group.h` and `src/bsgs/explicit.c` (spec §§7.1, 7.2, 9)

Interface (S3 will implement it with a chain; keep the header free of backend details):

```c
typedef struct canon_group_ops {
    uint64_t (*order)(const canon_group *);
    bool     (*contains)(const canon_group *, const uint32_t *p);
    /* spec 7.2: t minimising L^t lexicographically among t in G; H_out = pointwise stabiliser
       of L^t, exposed as orbit ids on the domain (orbit_id[v] = index of orbit containing v
       after the spec 7.1 ordering: each orbit sorted increasingly, orbits sorted lexicographically) */
    canon_status (*tuple_min)(const canon_group *, const uint32_t *L, uint32_t len,
                              uint32_t *t_out, uint32_t *orbit_id_out /* may be NULL */);
} canon_group_ops;
```

Explicit backend: closure by breadth-first generation in increasing discovery order under generator order, stored as a table of `|G|` dense arrays, then **sorted lexicographically** so that "least element" queries are table order. `tuple_min`: scan the table for the least `L^g`; on ties (only possible when `L` is not a full list) take the least `g`, which is well defined because the table is sorted. For the G stage the caller passes `F` (the singleton list in partition order), receives `u` with `F^u = M`, and the orbits of `G_M` pulled back through `u⁻¹`; the backend computes `G_M` by filtering the table and the orbits by union-find over the filtered elements. Record in a comment that this is O(|G|·n) per call and is replaced in S3.

### 4.3 `src/object/subset.c` (spec §§2.1, 7.1)

Subset over degree `n`: bitset plus sorted atom list. Action `x^g = {g[a] : a ∈ x}`. Initial P1 key: membership 0/1. Equality.

### 4.4 `src/encoding/wire.c`, `src/encoding/subset_stream.c` (spec §§4.1, 4.2)

`U16`, `U32`, `B` writers into a growable byte buffer with overflow checks. The subset stream: `43 4e 02 | U16(1) | U16(1) | U32(n) | U32(q) | records | U32(root)`, where the records are one atom record `01 U32(a)` per member in increasing `a` (height 0, sorted by record bytes, which for atoms equals numeric order) followed by one set record `04 U32(k) U32(ids…)` referring to atom indices `0..k-1`, and `root = k`. Empty subset: `q = 1`, one set record with `k = 0`, root `0`. Do not write a general DAG normaliser in S1; write this specialisation with a comment pointing to §4.2 and S5.

### 4.5 `src/partition/` (spec §§7.1, 10)

`lab`, `pos`, `cell_of`, cell boundaries in semantic order. `split(P, sig)` replaces each cell in place by its nonempty signature classes in increasing signature order, never reordering old cells (§7.1). Signatures for S1 are `uint32_t` keys (membership key, orbit index); sort members of a cell by key with a stable sort. Individualisation replaces cell `C` by `[{a}, C \ {a}]` in place (§7.1). Rollback restores the previous partition exactly; implement by snapshotting the arrays per depth (O(n·depth) memory, acceptable for S1; §11.2's trail/replay variants come in S8). The trace needs the cell-size list of the current partition in order.

### 4.6 `src/refine/p1.c` (spec §7.1)

The node loop exactly as written in §7.1:

```
append NODE(depth)
repeat:
    c0 = cell count
    O: for a non-graph root, every signature is empty: split is the identity; append STAGE_O(sizes)
    G: F = singleton atoms in current partition order
       (u, orbit_id) = group->tuple_min(F)      -- M = F^u, orbits of G_M pulled back via u^-1
       sig(v) = orbit_id[u[v]]
       P = split(P, sig); append STAGE_G(sizes)
    if cell count == c0: break
```

Note the pull-back: the backend returns orbit ids on the **target** labels, so the signature of `v` is the id of the orbit containing `u[v]`. One complete no-change sweep is always recorded, including at a discrete root and at `n = 0` (empty partition, one sweep, sizes list of length 0).

### 4.7 `src/search/p1_tree.c` (spec §§7.1–7.3, 11.1)

Unpruned DFS. At each node, after refinement: if all cells are singletons, append `LEAF` and evaluate the leaf; else choose the cell minimising `(size, position)` among cells of size `> 1` and, for each `a` in that cell in its current member order, individualise, recurse at `depth + 1`, roll back. Leaf: `L` = singleton order; `t = tuple_min(L)` (unique since `L` is a full list); image `x^t`; stream bytes; key `(trace, bytes)` compared lexicographically, trace first, bytes by unsigned lexicographic order with proper prefix smaller (§§4.3, 7.2). Keep the least key; on an equal key keep the lexicographically smaller `t` (§7.4 preamble: "minimise among the witnesses that actually attain that key"). Count `NODE` tokens; when the count would exceed `max_search_nodes`, abandon and return `CANON_CAPACITY_LIMIT` (§11.1: the quota counts the fixed reference traversal, so the outcome depends only on the input and the descriptor). Trace buffer and candidate buffers live in the workspace and are reused across solves.

**Witness note.** §3 defines a *deterministic witness* as the least image array among all `g` with `x^g = c`, which ranges over `Aut_G(x)·t` and needs the stabiliser (S4). S1 reports the least **leaf** witness attaining the minimal key, which is what §7.4's preamble prescribes for the golden cases and what the Python model computes. Say so in the header comment on `canon_result_witness` and in `S1-notes.md`.

### 4.8 `src/api/`

Handles are heap structs with a reference count; `*_release` frees at zero. The context owns the capacity defaults. `canon_problem_create` validates compatibility (objective, profile, encoding, order, degrees, capacity) and retains the group and object. `canon_workspace_create` allocates lazily on first solve to the problem's degree. `canon_solve` runs the search and builds an immutable result owning copies of trace, bytes and witness. Results never alias workspace memory.

### 4.9 `tools/canon-cli.c`

```
canon-cli p1-subset --n N --gens "a0,a1,...;b0,b1,..." --atoms "x,y,z" [--max-nodes K] [--id CASE]
```

`--gens ""` is the trivial group; `--atoms ""` the empty subset. Prints one `refs/compare/FORMAT.md` record: `CASE\t0001\tSTATUS\ttrace_hex\tbytes_hex\twitness` with the witness as comma-separated images, `-` for `n = 0`, empty hex fields when the status is not `COMPLETE`. Exit 0 on `COMPLETE`, 3 on any other status, 2 on usage error. The CLI links `libcanon` and uses only the public header.
