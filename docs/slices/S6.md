# Slice S6: labeling cosets and signed canonical images

**Goal.** The two remaining first-release objectives are available through the public API and the CLI: `CANONICAL_LABELING_COSET` (typed witness λ = ρt and the complete coset Aλ, §3.1) and `SIGNED_CANONICAL_IMAGE` (a validated character χ, a one-sided zero certificate, or a nonzero canonical monomial with its sign and complete-stabiliser evidence, §8.4). Characters are validated by the lifted group of §8.4. The end-to-end test checks both objectives against the Python model's labeling and signed constructions on the T1 tier.

Normative text: `docs/specification.md` v2.0 (cited §x): §§3, 3.1, 3.2, 4.3, 7.3, 7.4, 8.2, 8.4, 9.4, 11.1, 17, 20. Process: `docs/detailed-implementation-plan.md` §0, §0a, §7 (WP4.4). Prerequisites: S1–S5 landed. The S1 §2 rules and the conventions enforced in the S1–S5 reviews apply.

## 1. Scope

In scope:

- Signed groups: `canon_group_create_signed` taking a sign per generator; validation of χ by the lifted group on `Ω ⊔ {+,−}` (§8.4); a `character` operation on `canon_group_ops` returning χ(g) for a member `g`; both backends.
- `src/search/objectives.c`: the labeling-coset consumer (§8.2 row "Canonical labeling coset", §3.1 reconstruction) and the signed consumer (§8.4 reference algorithm, with the §7.3 generator fast path).
- Encoding: the labeling-coset payload `Group(A) || Perm(λ₀)` (§9.4 last paragraph, record type `08` semantics) and the signed zero payload `00` (§4.3).
- API: a labeling argument on the problem options (`rho`, an image array Ω → D_n), result accessors for the sign and for λ; `canon_result_encode` emitting `00` for a certified zero.
- CLI subcommands `labeling` and `signed`; FORMAT unchanged (sign via the `;sign=` suffix, λ in the witness field, the coset payload in `group_hex`).
- Tests: C unit tests; Python e2e tiers for both objectives against `checks/review_checks.py`'s labeling and signed constructions (the loops in its `run_v2`).
- READMEs; `docs/slices/S6-notes.md`.

Out of scope: the signed labeling reconstruction with the orientation σ_ρ (§3.1 last paragraph; record as deferred), `CONSTRAINT_ONE/ENUM`, SIGN-COVER (no shortcut: nonzero always uses the complete stabiliser, §8.4), xperm-style wrappers (M3c), pruning (S7), multi-limb orders.

## 2. Public API additions (provisional until M4)

```c
/* spec 8.4: generators with signs chi(g_i) in {-1, +1}.  Validates that the signs define a
 * homomorphism G -> {+-1} by constructing the lifted group on degree + 2 points (each generator
 * acts on Omega as given and swaps the last two points iff its sign is -1): chi exists iff the
 * subgroup of the lift fixing every point of Omega is trivial, i.e. iff |lift| == |G|.  Inconsistent
 * signs are CANON_INVALID_INPUT (spec 8.4 "Reject inconsistent signs").  degree + 2 must fit
 * uint32 (spec 11.1), else CANON_CAPACITY_LIMIT. */
canon_status canon_group_create_signed(canon_context *, uint32_t degree, const uint32_t *generators,
                                       size_t generator_count, const int8_t *signs, canon_group **out);
/* spec 8.4: chi(g) for a member g; CANON_UNSUPPORTED_ACTION for an unsigned group;
 * CANON_INVALID_INPUT if g is not in G. */
canon_status canon_group_character(const canon_group *, const uint32_t *g, int *sign_out);

typedef struct canon_problem_options {
    canon_witness_mode witness_mode;
    const uint32_t *rho;   /* spec 3.1: bijection Omega -> D_n as an image array of length degree;
                              required for CANONICAL_LABELING_COSET, must be NULL otherwise */
} canon_problem_options;

/* spec 8.4: +1 or -1 for a nonzero signed result, 0 for a certified zero; CANON_INVALID_INPUT
 * for any other objective or an incomplete result. */
canon_status canon_result_sign(const canon_result *, int *sign_out);
/* spec 3.1: lambda = rho t as an image array Omega -> D_n (CANONICAL_LABELING_COSET only). */
const uint32_t *canon_result_labeling(const canon_result *, uint32_t *degree);
```

`canon_result_witness` returns `t` for the labeling objective (the element of `G′` found on `D_n`) and, for a certified zero, the verified odd automorphism `a` (the certificate). `canon_result_bytes` returns `c`'s stream for a nonzero signed result and for the labeling objective; `canon_result_group_bytes` returns `Group(A) || Perm(λ₀)` for the labeling objective. `canon_result_encode` writes the single byte `00` for a certified zero (§4.3) and the stream otherwise. Flags (§3.2): labeling → `image_canonical`, `witness_valid`, `subgroup_verified`, `stabiliser_complete`, `encoding_complete`; signed zero → `zero_certified`, `witness_valid`; signed nonzero → `nonzero_certified`, `image_canonical`, `witness_valid`, `subgroup_verified`, `stabiliser_complete`, `encoding_complete`. Statuses: `COMPLETE`; `CAPACITY_LIMIT` on the quota (P1 nodes plus enumeration visits, as S4 decided); `UNSUPPORTED_ACTION` for a signed objective on an unsigned group or a labeling objective on a non-P1 profile; `INVALID_INPUT` for a missing or non-bijective `rho`.

## 3. Design

### 3.1 Signed groups and the lift (§8.4, §11.1)

Both backends keep an unsigned group for the ordinary operations and build a second group, the **lift**, on `n + 2` points from the lifted generators (`g̃ = g` on `Ω`, and `n ↔ n+1` iff the sign is −1). Validation: build the lift's chain (or explicit table) and compare orders: `|lift| == |G|` iff the projection kernel is trivial (the projection is onto, so `|lift| = |G| · |kernel|`); otherwise `INVALID_INPUT`. The identity generator with sign −1 and the §7.4 cases (`⟨[1,0]⟩` with sign −1 is valid; `⟨[1,0]⟩` with generators `[1,0]` twice and signs `+1, −1` is invalid) are tests. `character(g)`: `χ(g) = +1` iff the extension of `g` fixing both markers is a member of the lift, else −1 (one membership test; `g` must be a member of `G`, else `INVALID_INPUT`). Pin the lift's product rule by a test: the lift of a product is the product of the lifts (§8.4 "swaps compose by sign multiplication").

### 3.2 Labeling-coset consumer (§3.1, §8.2)

Given `ρ`, compute `x′ = x^ρ` (the S5 action on the root) and `G′ = ρ⁻¹Gρ` (conjugate the generators: `ρ⁻¹ g ρ` under `(pq)[v] = q[p[v]]`, i.e. `ρ⁻¹` first), build `G′` through the backend, run P1 on `D_n` for `t` and `c = x′^t`, set `λ = ρt`. Run the complete stabiliser consumer for `x` under `G` on `Ω` to get `A` (verified chain). The complete answer is `Aλ`; its payload is `Group(A) || Perm(λ₀)` with `λ₀ = canon_coset_least(A, λ, ∅)` (the least image array in `{aλ : a ∈ A}`; the S4 descent works unchanged since `λ` is a bijection of `{0..n−1}` in machine terms). Tests from §7.4: `Ω = (a,b)`, `ρ = [1,0]`, `G = 1`, `x = {a}` gives `t = id`, `λ = ρ`, `c = {1}`, `Aλ = {ρ}`; returning `id` is wrong. Representative change: `ρ′ = kρ` for `k ∈ G` gives the same `c` and the same coset payload; coordinate rename by `μ` gives the same `c` (the Python model's loop in `run_v2` is the oracle for both). Pin the product sides (`λ = ρt` is `ρ` first) by a non-commuting test.

### 3.3 Signed consumer (§8.4, §7.3)

1. **Generator fast path (§7.3).** If every generator fixes `x` then `A = G`: if any generator is odd return certified zero with that generator as the certificate; otherwise `A` is even, `c = x` and `s = +1` (return `x`'s stream, with the prescribed P1 trace computed by running P1, so the trace certificate stays available).
2. **Otherwise** run the stabiliser enumeration of §8.2 with a consumer that, on each hit `a`, evaluates `χ(a)`: on the first odd hit stop with a certified zero (the result holds `a`, verified by membership and `x^a = x`). On exhaustion `A` is complete and all its generators are even (assert `χ = +1` on each generator; §8.4); run P1 for `c = x^t` and return `s = χ(t)`, so `[x] = s[c]`.
3. The result's `encode` for zero is the single byte `00`; no stream exists. The quota counts enumeration visits plus P1 nodes, as in S4's deterministic mode.

Tests from §7.4: `n = 2`, empty subset, `⟨[1,0]⟩` with sign −1: `[1,0]` fixes `x` → zero; `x = {0}` → `c = {1}`, `s = −1`; `x = {1}` → itself with `s = +1`. Covariance: `s(x^h) = χ(h) s(x)` with `c` unchanged, for every `h ∈ G` (the model checks this). Cross-feed (§20): for every nonzero case `s(C(x)) = +1` where `C(x)` is the returned monomial. Certificate check: a tampered odd witness (not an automorphism, or even) is rejected by a `canon_result_verify_witness` extension that, for a zero result, checks membership, `x^a = x` and `χ(a) = −1`.

### 3.4 CLI and FORMAT

`canon-cli labeling --rho "1,0" ...` and `canon-cli signed --signs "-" ...` (one sign per generator, `+` or `-`), on top of the S1/S2/S5 object options and `--backend`. Records: labeling → objective `0005`, trace of the P1 run on `D_n`, `bytes_hex` = `c`'s stream, `witness` = `λ`, `group_hex` = `Group(A) || Perm(λ₀)`; signed → objective `0007`, `bytes_hex` = `c`'s stream or `00`, `witness` = `t;sign=±1` for nonzero or `a;sign=0` for zero, `group_hex` = `Group(A)` when complete else `-`.

## 4. Tests

- C: `test_signed_group.c` (validation cases; `character` on every element of T1 groups against a brute-force sign table; the lift's product rule; capacity `n + 2`), `test_labeling.c` (§7.4 case; representative change; coordinate rename; product side), `test_signed.c` (§7.4 cases; fast path; zero certificate verification and rejection of tampered certificates; covariance on hand cases).
- Python `test_e2e.py`, new tiers on T1 subsets and the G1 digraphs under both backends: **L1** every `ρ ∈ Sym(n)`: `λ ∈ Gρ`, `c` equals the model's `p1` on the transformed problem, the coset payload equals `group_bytes(A) + perm_bytes(min(Aλ))`, representative change and rename invariance as in `run_v2`; **Z1** every character of every T1 group (`review_checks.characters`): zero iff an odd stabiliser element exists; nonzero sign equals `chi[t]` with `c` equal to the unsigned P1 image; covariance over all `h`; `s(C(x)) = +1`. Also `canon_stream_validate` on every nonzero output and the hexdump tool on it.
